## 1. Batch install ingress: process globals and lifecycle

**Verified evidence.** `internal/agent/batch_install_ingress.go:144-149` declares `coordinatorBatchBindings sync.Map` and process-wide `processBatchBinding atomic.Pointer[...]`. `BindCoordinatorBatchRuntimeBindings` stores the coordinator binding, attaches its disk registry to coordinator/root agent, and uses `CompareAndSwap(nil, bind)` for the first-wins process fallback (`:164-201`). Coordinator dispatch/private-fetch accessors use the coordinator binding (`:204-227`); only `processCoordinatorBatchBinding` reads the process pointer (`:229-232`). `BindRuntimeIngress` is intended before invocation (`:234-244`). App setup binds batch controls only when ingress is present (`internal/app/app_agent_setup.go:178-186`); ephemeral Apps bind their capability manager (`:161-177`). Existing tests verified by declaration search: `TestBindCoordinatorBatchRuntimeBindings_BindsBuiltRootAgentAndOrphanEnqueueRetainsBinding` in `internal/agent/root_agent_diskcaps_test.go:22`; `TestAgentDriverRunsPinnedLeaf` and `TestAgentDriverFailsClosedWithoutBinding` in `internal/agent/batch_install_tools_test.go:301,352`; `TestBatchCLIBindOwnsConstructionScopeUntilRelease` in `internal/agent/batch_construction_scope_boundary_test.go:127`. Fixtures save/replace/reset global state (`batch_install_tools_test.go:308-309,353-354,372-373`; `batch_install_p1_test.go:174-176`; `batch_construction_scope_boundary_test.go:138-141`). No production teardown was found in the cited setup/ingress paths.

**Design and invariant.** Replace process-wide mutable ownership with an instance-owned binding handle (owned by the App/runtime/coordinator association), with explicit idempotent `Release` that removes only that exact registration and cannot clear a newer binding. Preserve coordinator-local dispatch, flag-off behavior, and install-before-Invoke. Fallback options: (a) retain first-wins process fallback only for compatibility, never as authority for App/coordinator lookup; or (b) remove it after inventorying all fallback callers and migrating them to explicit bindings. Do not use “latest App” or unconditional map deletion. Concurrent release/install/lookup must be race-safe: test simultaneous release against active invocation and concurrent old-handle release versus replacement install, asserting an old release neither revokes a live reader nor erases the replacement; test repeated release and two-App separation.

**Independently mergeable commit sequence (each commit builds on the previous; keep each behavior-preserving until its stated cutover).**
1. **Characterize current behavior** — add replacement/two-App and release-race characterization tests in `internal/agent/batch_construction_scope_boundary_test.go` and/or `internal/agent/batch_install_tools_test.go`, alongside the existing binding tests. Touched files: those existing test files only. Preserve current global setup/cleanup in test fixtures; characterize coordinator-local lookup, first-wins fallback, and cleanup behavior before changing ownership.
2. **Add an instance handle** — in `internal/agent/batch_install_ingress.go`, have binding installation return an identity-bearing handle with idempotent `Release`; release removes only its matching coordinator registration and does not revoke an active invocation or erase a replacement. Update/add focused tests in `internal/agent/batch_construction_scope_boundary_test.go` and `internal/agent/batch_install_tools_test.go`. Touched files: ingress implementation and these existing tests; keep existing callers source-compatible if possible (or migrate them in this commit).
3. **Wire App lifetime** — thread/store the handle through the known setup path `internal/app/app_agent_setup.go:161-186` and release it at the confirmed App/runtime shutdown path. Touched files: `internal/app/app_agent_setup.go`, the actual existing App shutdown-owner file (unresolved; must identify before implementation), and focused existing `internal/app` lifecycle tests plus relevant `internal/agent` binding tests. **The shutdown owner is not established by inspected setup/ingress paths; do not wire release to setup teardown or guess an owner.** This commit is independently mergeable only after that owner is located and its lifecycle contract verified.
4. **Migrate/remove fallback** — inventory every `processCoordinatorBatchBinding`/process fallback caller, migrate each to the explicit instance/coordinator handle, then remove the first-wins `processBatchBinding` fallback from `internal/agent/batch_install_ingress.go`. Touched files: that implementation and the actual caller files/tests found by inventory; do not remove fallback while any caller still relies on it. This is a separately reviewable final cutover; retaining it temporarily as compatibility-only is acceptable.

**Cost / consequence / recommendation.** Small characterization: roughly 40–80 test lines in 1 existing test file; lifecycle repair is roughly 80–160 production/test lines across 2–4 existing files (ingress, App setup, confirmed shutdown owner, focused agent tests). Risk is high: races can revoke a live binding or retain authority across logical shutdown. Doing nothing leaves process fallback and lifetime coupled to reachability, with no deterministic revocation. **Do now:** characterize binding/replacement and locate the actual App shutdown owner; then implement identity-checked release only with that owner confirmed. **Do later:** remove the compatibility process fallback after all callers are inventoried and migrated. **Drop:** a declaration-only move as a standalone change; it cannot repair lifecycle and costs review churn without behavior benefit. Proposed named oracles: `TestBindCoordinatorBatchRuntimeBindings_BindsBuiltRootAgentAndOrphanEnqueueRetainsBinding`, `TestAgentDriverRunsPinnedLeaf`, `TestAgentDriverFailsClosedWithoutBinding`, `TestBatchCLIBindOwnsConstructionScopeUntilRelease`, plus new `TestCoordinatorBatchBindingReleaseIsIdempotent`, `TestCoordinatorBatchBindingReleaseDoesNotClearReplacement`, and `TestCoordinatorBatchBindingReleaseRacesActiveInvocation` (new names are proposals). ## 2. Coordinator capabilities: typed construction-time bundles

**Verified evidence.** `internal/agent/coordinator.go:134-256` defines the 34-method `Coordinator`; enlarging it burdens all implementers/fakes. `internal/app/app_agent_setup.go:152-222` probes `session.SessionExecutionRequirementStore`, wires disk/batch facilities via setters, and keeps `WakeScheduleController` optional by type assertion. Existing relevant seams verified in source: `SetCoordinatorExecutionRequirementStore` (`internal/agent/disk_provider_continuation.go:238-241`), `SetCoordinatorBatchHeldAnswerSink` (`internal/agent/coordinator_agent_inject_batch.go:255`), `SetCoordinatorSessionNoticeStore` (`internal/agent/batch_rehome_coord_runtime.go:198`), and `SetBatchDriverClaimer` (`internal/agent/batch_cutover_driver.go:24`). `internal/agent/coordinator_iface_assert.go:3-13` checks only `AutoTurnHolder`, `ReactionDebtSource`, and `ParkedSubAgentWorkReporter`; `coordinator_iface_assert_test.go:18` contains `TestCoordinatorOptionalInterfaces_ReachableThroughCoordinatorValue` (test declaration verified), not blanket coverage of every setter/assertion.

**Proposal/invariant.** Do not merely split the interface. Keep `Coordinator` and optional interfaces for compatibility, but incrementally replace post-construction assertion/setter chains with typed, construction-time capability bundles in the existing `internal/agent` and `internal/app` packages. A bundle groups only capabilities needed by one construction mode (for example, `BatchRuntimeCapabilities` containing ingress, model controls, disk registry, and optional live reader; a separate `SessionExecutionCapabilities` containing the requirement store and notice store). Coordinator construction receives explicit typed options/bundle; validate required fields once and fail construction for a mode that requires a missing capability. Optional absent capabilities remain explicit nil/disabled states. This makes wiring discoverable and removes temporal “construct, then setter” gaps without expanding the base interface or creating new packages.

**Commit sequence.** 1) Define the first concrete typed bundle alongside the existing coordinator in `internal/agent/coordinator.go`, and pass it at construction from `internal/app/app_agent_setup.go`; migrate batch ingress/model-control/disk-registry wiring now performed through `BindCoordinatorBatchRuntimeBindings`/setter paths while preserving semantics. Add focused construction tests in existing `internal/agent/batch_install_tools_test.go` and/or `internal/app` setup tests (select exact existing setup test file during implementation; do not invent a test name as existing). 2) Convert the execution-requirement store and session-notice-store setter path to a separate typed bundle in `internal/agent/coordinator.go` and `internal/app/app_agent_setup.go`; cover present/absent behavior in the existing `internal/agent` and `internal/app` tests. 3) Convert remaining setters one capability family at a time, each with compile-time assignment checks beside `internal/agent/coordinator_iface_assert.go` where a concrete required interface is proven; do not split packages or introduce a new package. Keep the existing reachability test and compile assertions passing unchanged as the pure-move oracle if declarations are relocated; for a true behavior change, add tests beside the exact existing wiring.

**Cost / consequence / recommendation.** First batch bundle is an estimated 80–180 changed lines across 3–5 existing files (`internal/agent/coordinator.go`, `internal/app/app_agent_setup.go`, the relevant `internal/agent` batch tests, and an existing `internal/app` setup test selected after locating it). Later capability families add roughly 30–80 lines each across 2–4 files. Risk: moderate; hidden optional behavior can be omitted and fake/construction sites can diverge. Doing nothing keeps construction order temporal and lets required capabilities be silently absent; splitting the broad interface first would instead force unnecessary implementer/fake churn. **Do now:** first typed batch bundle with absent/present behavior tested. **Do later:** session-execution bundle and further families only when real App setup requires them. **Drop:** broad `Coordinator` interface split absent measured user-facing benefit. Proposed named oracle tests: existing `TestCoordinatorOptionalInterfaces_ReachableThroughCoordinatorValue` and focused new `TestBatchRuntimeCapabilitiesRequiredFieldsFailConstruction`, `TestBatchRuntimeCapabilitiesOptionalReaderMayBeAbsent`, `TestAppSetupPassesBatchRuntimeCapabilities` (new test names proposed; exact app test file must be identified before implementation). Pure-move-only relocations must preserve declaration list and test count via CLAUDE.md:79–88 command oracle; behavioral bundle changes are not pure moves.
