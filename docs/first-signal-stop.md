# Остановка CLI по первому сигналу

CLI устанавливает единый аварийный обработчик в начале main, до проверки рабочего каталога, обычной загрузки конфигурации и командного журнала. Инициализаторы импортируемых пакетов Go выполняются раньше main; работа, уже выполненная в них, этим не отменяется.

- Unix: первый SIGINT завершает процесс с кодом 130, SIGTERM — 143.
- Windows: Ctrl+C, Ctrl+Break, закрытие консоли, logoff и shutdown направляются в тот же путь с кодом 130. При отсутствии присоединённой консоли ОС может не доставлять console events; TerminateProcess не перехватывается.
- Ctrl+C в raw-mode интерфейсах также вызывает аварийную остановку.

В этом пути нет App.Shutdown, финального save/flush, SQLite Close/checkpoint, heartbeat, удаления lock-файлов, end-записи аудита или сообщения на stdout/stderr. Вывод мог быть перенаправлен в файл, поэтому обработчик ничего не печатает. Незавершённый вывод и ещё не закоммиченное состояние могут быть потеряны. Терминальный интерфейс не получает обычную процедуру восстановления; при необходимости терминал восстанавливается оболочкой или оператором.

Отслеживаемые деревья процессов завершаются системными средствами. На Unix обработчик использует опубликованный снимок собственных групп без ожидания mutex; поздняя регистрация после stop уничтожает зарегистрированную группу. На Windows используются собственные Jobs, а при занятом реестре — корневой KILL_ON_JOB_CLOSE Job CLI. Если ОС не позволила присоединить процесс к Job, эта дополнительная гарантия недоступна. Реестр не означает владения произвольным процессом, который самостоятельно отделился от группы или вышел из Job.

Новые отслеживаемые CLI-provider запуски после начала stop отклоняются. Независимый таймер вызывает прямой выход через 250 мс, если системная зачистка не вернулась. Это бюджет после начала обработки сигнала, не гарантия wall-clock при остановленном планировщике ОС. Внутри окна до выхода могут ещё выполняться ранее начатые потоки. Уже переданное ядру I/O и отложенная запись ОС не могут быть гарантированно отозваны. Абсолютный запрет всех filesystem syscalls сторонних библиотек до exit здесь не заявляется.

Обычное успешное завершение команды, программная отмена контекста и закрытие SDK сохраняют прежние контракты. SDK не устанавливает этот process-global handler и не завершает host-процесс. Остановка локального API-клиента также не означает подтверждённую отмену работы удалённого сервера: для этого нужен отдельный API-запрос отмены.

После аварийного выхода уже закоммиченные данные остаются в SQLite; незавершённая транзакция восстанавливается средствами SQLite при следующем открытии. Файлы блокировок могут остаться: следующий процесс проверяет реальное OS-lock/PID владение, а не считает существование файла доказательством живого владельца. Финальных исправляющих записей на выходе нет.

## Проверки

В CI выполняются пины первого сигнала, независимого дедлайна, raw Ctrl+C и отключения конкурирующих command handlers; subprocess-проверки SIGINT/SIGTERM и реального Windows console break. В subprocess занят mutex аудита, открыта незавершённая SQLite-транзакция и жив дочерний процесс, игнорирующий interrupt. Проверяется выход после первого сигнала, закрытие дерева, отсутствие deferred marker и целостность БД после повторного открытия. Диагностика subprocess печатается только при падении теста.
