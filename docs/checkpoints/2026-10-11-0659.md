## Decisions
- Токен читается из памяти перед каждой отправкой (диск на горячем пути не читаем); порядок публикации: память → журнал → конфиг (решение оператора); «обновление токена всегда сохраняется, никаких перелогинов из-за кривостей» — поэтому журнал + неограниченные повторы вместо «3 попытки и сдаёмся».
- Везде один арбитр токенов: выход из аккаунта побеждает; токен-предшественник (по дайджесту refresh token) не побеждает при любом сроке; иначе позднейший срок, при равенстве — диск. Повреждённый журнал → карантин (5 штук), обмен не блокируем; ошибка чтения журнала — не порча.
- Серию ревью #1289 остановил после 11 заходов (правило остановки ревью из CLAUDE.md): узкие искусственные межпроцессные чередования не чиню; открытый кейс записан в коммите. Слияние — только после моей проверки (полные пакеты, race, lint, мутанты).
- Зависимости: критический grype (x/net) чинится обновлением зависимости, это не повышение версии проекта.
- Пуш — только по просьбе оператора; перед пушем гонять зеркало pre-push вручную (хук не подключён), но на нагруженной машине зеркало шумит (чужие процессы держат CPU ~99%).
