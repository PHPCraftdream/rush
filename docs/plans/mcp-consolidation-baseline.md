этапа 1). Этап 0.4 плана `docs/plans/2026-09-09-mcp-consolidation-plan.md`.

Назначение: этап 3 обещает «число тестов не убавилось» и «`init.go` < 2000
строк». Это цифры, с которыми сравнивать. Любое расхождение по тестам в
меньшую сторону на шагах 3.1–3.9 — стоп-сигнал, а не повод округлить.

## Отклонение от буквы плана

План требует снять линию «до первой правки». Фактически снято **после**
этапа 0.2 (задача #899). Причина: параллельный запуск двух тяжёлых
`-race`-прогонов на этой машине уже приводил к `ERROR_COMMITMENT_LIMIT`
(errno=1455), поэтому базовый прогон ждал завершения агента #899.

Для сравнения это лучше, а не хуже: этапы 1–3 стартуют именно из этого
состояния. Прод-код в #899 не менялся (добавлен только тест), поэтому
LOC-метрики от «до первой правки» не отличаются; число тестов в `mcp/`
включает один новый оракул.

## Как перепроверить

```bash

go test -race -count=1 -p 2 ./internal/app/... ./sdk/... ./internal/server/...
go test -list '.*' ./internal/agent/tools/mcp/ | grep -c '^Test'
wc -l internal/agent/tools/mcp/init.go
sed -n '/^var (/,/^)/p' internal/agent/tools/mcp/init.go
```

Длительные прогоны запускать только фоном; никогда не два тяжёлых
одновременно.
