# План: декомпозиция файлов > 1000 строк и правило, которое это держит

Дата: 2026-09-09. Базовый коммит: `158a905cc`. Задачи в сессии: #924–#927.

Правило оператора: **ни один рукописный файл исходного кода не больше 1000
строк.** Файл больше — декомпозируется. Правило подкрепляется двумя слоями
проверки (линтер + pre-push guard), чтобы не протухнуть — как протухала
любая договорённость в этом репозитории, не подкреплённая проверкой.

Это замена отменённой миграции глобалов MCP (см. решение в
`docs/plans/2026-09-09-mcp-consolidation-plan.md`): та давала 33 строки за пять
дней риска; эта — чисто механическая, с риском около нуля и измеримым
результатом.

## 1. Ключевое решение: «в папку» для Go значит «в файлы того же пакета»

Разрез делается **в той же директории, новые файлы — `package mcp`** (и т.д.).
**Не под-пакет.**

Почему это важно и не обсуждается внутри задач:

- Go считает все файлы директории одним пакетом. Перенос декларации из
  `init.go` в `lease.go` не меняет **ничего**: ни видимость, ни импорты, ни
  порядок инициализации `var` (он зависит от зависимостей между переменными,
  а не от файла). Это чистое «в каком файле лежит», риск ≈ 0.
- Под-пакет (`mcp/lease/`) потребовал бы экспортировать всё, что пересекает
  границу — включая 9 глобалов `init.go:366-377`. Это отменённая миграция
  глобалов через чёрный ход: тот же нулевой выигрыш в строках, но с реальным
  риском и переписыванием 54 внешних вызовов.

Проверено для `init.go` перед стартом: 0 build-тегов, 0 `func init()`,
0 `//go:embed`, 0 `//go:generate`, 328 деклараций верхнего уровня. Ничего
файл-специфичного — разрез механический.

## 2. Оракул сохранности — чем доказывается, что это чистое перемещение

Для каждого разрезанного файла, помимо `go build`/`go vet`/`gofmt`:

```bash
grep -hE '^(func|type|var|const) ' <старый>.go | sort > before.txt
cat <новые...>.go | grep -hE '^(func|type|var|const) ' | sort > after.txt
diff before.txt after.txt          # ОБЯЗАН быть пуст
```

Ни одна декларация не потеряна, ни одна не задвоена. Дополнительно:
`wc -l` суммы сходятся с точностью до добавленных строк `package` и
import-блоков; `git diff --stat` читается как перемещение (вставки ≈
удаления). Для тестов — `go test -list '.*'` до == после.

Это дешёвый, сильный, машинный оракул. Без него «разрезал файл» —
утверждение, с ним — факт.

## 3. Два слоя проверки правила

**Слой 1 — линтер (то, что просил оператор).** `revive` в `golangci-lint`
v2.13 (закреплён в `.githooks/pre-push:45` и `.github/workflows/lint.yml`)
имеет правило `file-length-limit`; наличие подтверждено в кэше модулей.
Настраивается в `.golangci.yml`: `max: 1000`, считать сырые строки (без
`skipComments`/`skipBlankLines`), чтобы метрика совпадала с `wc -l` и со
слоем 2. Срабатывает в CI-lint и в редакторах.

**Слой 2 — pre-push guard `.githooks/check_file_size.sh`** по образцу
существующих `check_*.sh`. Нужен, потому что: (а) guard детектирует
генерированные файлы по маркеру `// Code generated ... DO NOT EDIT.`, а не по
имени; (б) у него есть храповик с дружелюбным «удали X из allowlist»; (в) он
покрывает и Go, и TypeScript одной метрикой.

**Слой 3 — oxlint в `web/`** (#928, `web/.oxlintrc.json`): правило `max-lines`
уровня `error`, тот же максимум 1000 и та же сырая метрика
(`skipBlankLines: false`, `skipComments: false`). В первой редакции плана
здесь было сказано, что «в `web/` нет ESLint, TS линтером не покрыт» — это
перестало быть правдой: линтер добавлен по отдельной просьбе оператора, и
`store.ts` держит `max-lines` override с комментарием, привязывающим его
снятие к #927.

**Храповик — обязательное свойство обоих слоёв.** Правило ставится
**сейчас**, пока 20 файлов его нарушают, и не блокирует push. Для этого:
- guard читает `.githooks/file_size_allowlist.txt` (`<путь> <строк>`):
  файл из списка может быть > 1000, но **падает, если вырос**; и падает,
  если стал ≤ 1000 и не удалён из списка (список обязан быть честным);
- линтер исключает те же пути через `linters.exclusions.rules`;
- **единый источник истины**: selftest guard'а сверяет allowlist с
  исключениями в `.golangci.yml` в обе стороны — расхождение валит pre-push.

Так долг может только уменьшаться, а каждая задача split-* удаляет свой
файл из списка как последний шаг.

## 4. Задачи и порядок

Стратегия для всех — `/wcrush`: **фаза 1** (разрез + компиляция + статика +
оракул сохранности, без прогонов) параллелится по пакетам; **фаза 2**
(прогон тестов пакета) — по одному, по разрешению оркестратора. Именно та
схема, ради которой `/wcrush` и написан: разрезы разных пакетов не
конфликтуют по файлам, а тяжёлые `-race`-прогоны сериализуются, чтобы не
ловить `ERROR_COMMITMENT_LIMIT`.

### #924 [split-0] — правило и оба слоя проверки. *Идёт.*
Guard + selftest + allowlist + revive-правило + сверка списков + шаг в
pre-push. Правило одним абзацем в fork-`CLAUDE.md` (правит оркестратор).
Выход: guard и линтер зелёные на текущем дереве благодаря храповику;
selftest доказывает, что 1001-строчный файл падает, генерированный —
проходит, выросший allowlist-файл — падает.

### #925 [split-1] — `init.go` → ~8 файлов пакета `mcp`. *Идёт.*
Один агент (резать один файл несколькими — конфликты). **Карта разреза уже
написана** — это реестр `docs/mcp-invariants.md`: колонка «Where» каждого
инварианта называет диапазоны строк одного concern'а. Ориентир: `owner.go`,
`admission.go`, `lease.go`, `session.go`, `mutation.go`, `refresh.go`,
`uncertainty.go`, `transport.go`, остаток в `init.go`; ≤ 900 строк каждый
для запаса. **Переякорить реестр — часть этой задачи**: все 25 строк «Where»
после разреза врут, а врущий реестр хуже отсутствующего.
Фаза 2: `mcp` с `-race -parallel 2` (~85 с), затем `app`/`sdk`/`server` по
одному (импортируют `mcp`). Ожидаемое число тестов: 234.

### #926 [split-2] — остальные 12 прод-файлов, по пакетам, параллельно.
Блокируется #924 и #925. Девять пакетов → до девяти агентов в фазе 1
одновременно; фаза 2 — девять последовательных прогонов. Особое внимание:
`internal/session` — «battle-tested» подсистема по fork-`CLAUDE.md`, разрез
механический, но фаза 2 обязательно с `-race`; `internal/cmd/migrate.go`
мержить после #922 (тот правит соседние файлы пакета). Мелкие файлы
(1005–1102) часто режутся выносом одной группы функций.

### #927 [split-3] — 6 тест-файлов и `store.ts`. Блокируется #926.
Тесты `mcp/` резать по INV из карты «Test → invariant» реестра (готовая
группировка), прод-сеймы (`serverLeaseHooks` и др.) не двигать. `store.ts` —
проверка компиляции через `pnpm typecheck` (шаг уже есть в pre-push); логику
не трогать, только файлы; fork-`CLAUDE.md` запрещает возвращать
localStorage-персистенцию.

  revive в `.golangci.yml` удалены.
- Оракул сохранности пуст для каждого разреза; число тестов по пакетам не
  уменьшилось (`mcp`: 234).
- `golangci-lint run` и `.githooks/pre-push` зелёные без исключений.
- Реестр инвариантов переякорен; каждый из 25 INV сохраняет живой оракул.
- Три зелёных прогона CI подряд (задача #918 общего плана).

## 6. Что специально НЕ делается

- Под-пакеты. Ни для одного файла.
- Изменение поведения, переименования, «заодно почистить». Это рефакторинг
  с границей «поведение не меняется»; функциональные правки — вне scope.
- Разрез генерированного кода.
- Правило задним числом для `docs/` и других не-кодовых файлов.
