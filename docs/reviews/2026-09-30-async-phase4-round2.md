### W2-STORE — db/session (agent `store2`)

- **R2A-1 (P1)** the orphan-lock reaper `purgeOrphanHostLockFiles` (`async_job_recovery.go`) can unlink the lock file of a host that is still
  registering: `RegisterHost` (`host_lock.go`) creates+locks `hosts/X.lock` and only then inserts the `async_hosts` row; a reaper that finds
  "file without row" and wins `flock` unlinks the file; the registrant then locks the unlinked inode and inserts its row → all probes of X see
  ENOENT = "dead" for the host's whole life (jobs marked `interrupted` while running, driver marker treated dead, two drivers). Other
  interleaving: registrant's lock attempt fails with `ErrLockContended` → async tool error / driver claim falls back to in-memory marker.
  Fix: insert the `async_hosts` row BEFORE creating the file (so "file without row" is never a registering host), or create+lock a temp file and
  rename into place; also make the reaper skip files younger than the registration window only if that is provably safe (prefer the ordering fix).
- **R2A-2 (P1)** lock-order inversion: `ensureHost` (`async_job_store.go`) holds `s.mu` across `RegisterHost` (a writer-connection DB call, single

  Fix: never hold `s.mu` across I/O (register outside the mutex, publish under it / atomic host id), never take `s.mu` inside a writer tx
  (capture host id before `BeginTx`).
