## R14-1/R14-2/R14-3 (eab5d508): unified no-real-workspace capability

**Статус: корректно, P0/P1 закрыты.**

### R14-1 (P0): applyNoRealWorkspaceToolFloor

`internal/agent/coordinator_tools.go:542` — `applyNoRealWorkspaceToolFloor` добавлен как финальный фильтр `AllowedTools` после worker-toolset layering и folder-scope re-adds. Корректно:
- проверяет `cfg.Options.NoRealWorkspace` (nil-safe);
- определяет `customDisk` как `disk != nil && disk != tools.OSDisk()`;
- вырезает `noRealWorkspaceForbiddenTools` (bash, run_command, download, edit, multiedit, write, view, glob, grep, ls);
- при отсутствии customDisk вырезает весь `fs_*` семейство.

`internal/agent/coordinator_tools.go:173` — `workerToolNames` включает `edit, multiedit, write, bash, todos, download, fetch, ask_question`. Из них реальный disk/command доступ имеют `edit, multiedit, write, bash, download` — все они в `noRealWorkspaceForbiddenTools` и будут вырезаны полом. `todos, fetch, ask_question` — не трогают реальный диск, остаются корректно.

### R14-2 (P0): ExecuteRun hard-refuses FolderScopes на no-real-workspace

`internal/app/app_run.go:660` — precondition перед любой canonicalization/provider traffic:
```go
if cfgOpts.NoRealWorkspace && len(overrides.FolderScopes) > 0 &&
   (overrides.DiskProvider == nil || overrides.DiskProvider == tools.OSDisk()) {
    return nil, errors.New(...)
}
```
Корректно: абсолютные scope Dir (которые раньше проходили через SmartJoin мимо sentinel guard) теперь отклоняются на входе. Opposite-direction checks (DiskProvider без FolderScopes, DiskProvider + command-keeping scope) сохранены ниже.

### R14-3 (P1): sdk.LibraryVirtualRoot → function

`sdk/library_mode.go:145` — `func LibraryVirtualRoot() string { return tools.LibraryVirtualRoot }`. Корректно: compile-time защита от reassignment, embedder больше не может развести SDK-корень и internal guard. README обновлён. Все call sites обновлены (включая тесты).

### Небольшое замечание по архитектуре (не bug)

`agentic_fetch` отсутствует в `noRealWorkspaceForbiddenTools`. Его защита сегодня опирается на два других механизма: (1) `libraryEphemeralDisabledTools` удаляет его из начального набора, (2) он отсутствует в `workerToolNames` и `folderScopeOpForTool`, поэтому layering не может его вернуть.

Это корректно здесь и сейчас, но менее robust, чем наличие в floor: если в будущем `agentic_fetch` добавят в `workerToolNames` или `folderScopeOpForTool`, floor его не вырежет. Остальные реально-опасные инструменты защищены именно floor'ом.

## Canonicalization fixes (b253bb70, c108a2d8, 678b5103)

**Статус: корректно, единый паттерн.**

Все три коммита фиксят один класс хост-топологии: `t.TempDir()` не guaranteed canonical на некоторых CI runner'ах (macOS `/tmp` → `/private/var`, junction на Windows temp drive). Production код (`resolveScopedPath`) канонизирует через `EvalSymlinks`, поэтому тесты, сравнивающие raw `t.TempDir()` против resolved путей, получают разные namespace'ы и false-fail.

Фикс — `filepath.EvalSymlinks(t.TempDir())` once up front — применён в:
- `b253bb70`: 3 symlink tests (`fs_scope_test.go`, `r5_2_canonicalize_folder_scope_test.go`, `r6_2_fs_list_find_result_resolution_test.go`);
- `c108a2d8`: 12 fake-disk + rebuild scope tests (`fs_provider_fake_test.go`, `r5_3_calloptions_durable_roundtrip_test.go`, `rebuild_folderscope_spec_test.go`);
- `678b5103`: `testEnv` в `common_test.go` (canonicalizes `workingDir` после `MkdirAll`) + `absWorkingDir` в `coordinator_disk_provider_test.go` (добавлен `EvalSymlinks` после `Abs`).

Call-site audit (100+ `testEnv` callers, 3 `absWorkingDir` callers) подтвердил, что ни один тест не зависит от raw spelling для literal string comparison.
