Дата: 2026-08-27. Статус: решение принято, код не написан.

Ответ на `D:\dev\cc-arch-hands\docs\rush-backend-requirements.md` — заметки
по итогам живого исследования на стороне `cc-arch-hands`, где `rush run`
рассматривается вторым бэкендом к `agent-tree.js`.

Каждое утверждение исходного документа проверено по коду этого
репозитория, а не по описанию поведения. Ссылки вида `файл:строка`

## 1. Что подтвердилось при проверке

Пять из шести эмпирических утверждений исходного документа верны.

**§2.2 — `--session` привязан к cwd и при промахе тихо создаёт новую
сессию.** Подтверждено. `internal/cmd/run.go:693-701`: `resolveSessionID`
ищет сессию по точному UUID или префиксу хеша; при неудаче управление
**проваливается дальше с сырым значением**, и ветка get-or-create создаёт
сессию, чей ID равен пользовательской строке буквально. Ошибки не
возникает по конструкции — не «баг в обработке», а отсутствующий контракт.

**§2.3 — стоимость в конверте нулевая.** Подтверждено, но причина не та,
которую предполагает исходный документ. См. раздел 3.3 ниже — это самая
существенная поправка во всём ответе.

**§3.4 — фактически использованная модель в конверте отсутствует.**
Подтверждено. `runResult` (`internal/app/app_run_result.go:21-72`) не несёт
ни модели, ни провайдера, ни effort.

**§3.5 — системный промпт персистентен на сессию.** Подтверждено
дословно: `internal/app/app_run.go:77` —
`SystemPrompt string // persisted on the session (Sessions.UpdateSystemPrompt)`,
запись выполняется на `app_run.go:511-512`.

**§3.6 — `tool_calls` несёт только имена.** Подтверждено:
`toolCallStat{Name, Count}` (`internal/app/app_run_result.go:83-86`).

## 2. Что не подтвердилось — и почему это меняет вывод документа

Исходный документ помещает `--restrict-run` в «тот же категориальный
разряд, что и `--allowedTools`/`--disallowedTools` у Claude Code, с той же
дырой». Разряд другой, и это не придирка к формулировке — из этого следует,
что часть работы, запланированной в §4.2 исходного документа, для
rush-бэкенда уже сделана.

**Модель Claude, которую проверял §2.1:** полный тулсет, запрещены
конкретные пути, эвристика разбирает командную строку. `node -e "…"`
проходит, потому что путь не виден как аргумент — он вычисляется внутри
кода, который интерпретатор получает строкой.

**Модель rush `--restrict-run`:** deny-by-default. Если единственный
паттерн — `--allow-bash 'git diff'`, то `node -e "…"` не матчит ни одного
разрешающего правила и отклоняется. Обход из §2.1 к rush **не
применяется** — не потому, что он предусмотрен и закрыт, а потому что
разрешающего правила для `node` просто нет.

Механика (`internal/permission/runallowlist.go`):

- Формы паттернов: `'cmd args'` (префикс по границе слова), `exact:`,
  `glob:`, `regex:` (`compileBashPattern`, строки 195-251).
- Первые три отказываются матчить составную команду:
  `bashCommandAllowed` вызывает `shell.IsCompoundCommand` и пропускает
  такие команды (строки 280-320). То есть `--allow-bash 'ls'` физически не
  может авторизовать `ls && rm -rf /`.
- От compound-guard освобождён только `regex:` — сознательно, как
  явный выбор оператора.

Дыра в этой модели существует ровно тогда, когда оператор сам напишет
разрешающий паттерн (`glob:node *`, широкий `regex:`). Это ошибка
конфигурации, а не свойство механизма.

**Практическое следствие для §4.2 исходного документа.** Классы
способностей `reader` / `writer` на rush существуют сегодня — это
композиция флагов, а не запрос фичи:

```
# reader — чтение, ноль записи, ноль исполнения
rush run --restrict-run \
         --allow-tool view --allow-tool grep --allow-tool glob \
         ...

# writer — плюс запись в собственную ячейку
rush run --restrict-run \
         --allow-tool view --allow-tool grep --allow-tool glob \
         --allow-tool edit:write --allow-tool write \
         ...
```

Ни одного `--allow-bash` — и интерпретатора в тулсете нет не потому, что
он в блок-листе, а потому что deny-by-default. Это дословно та граница,
которую §4.2 исходного документа называет настоящей.

Второй, ещё более прямой механизм — `options.disabled_tools` в
`rush.json`: тул удаляется из тулсета целиком, до того как модель его
увидит. Для `reader`/`writer` это точнее соответствует формулировке
«интерпретатора просто нет в тулсете», потому что снимает вопрос об
уровне, на котором работает запрет.

`builder` остаётся признанно небезопасным — здесь исходный документ прав
без оговорок. Но заметим: compound-guard закрывает именно тот класс
инцидентов, который §4.3 описывает как почти все реальные (опечатка,
не злоумышленник). То есть рекомендация §4.3 в rush уже реализована на
уровне механизма, а не только названа.

## 3. Что меняем

Порядок — по ценности для заявленной цели, а не по номерам исходного
документа.

### 3.1. `run.deny_paths` + `--deny-path` — путевой скоуп для тулов

**Этого пункта нет в исходном списке, и он важнее остальных.**

`--allow-tool` сегодня не имеет никакой гранулярности по путям. Проверено:
`allowTools map[string]struct{}` с ключами `tool` и `tool:action`, матчинг
`toolAllowed(toolName, action)` (`internal/permission/runallowlist.go:78-82,
134-147`). Сказать «`view` везде, кроме `_meta/**`» невозможно — только
всё или ничего.

Для исходной цели документа — спрятать `_meta/` от узла, которому `view`
нужен по делу — это и есть блокер. Здесь rush **слабее** claude'овских
path-паттернов, и это ровно противоположно тому, что предполагает §3.1
исходного документа.

Добавляем:

```json
{ "permissions": { "run": {
    "restrict": true,
    "allow_tools": ["view", "grep", "glob"],
    "deny_paths": ["_meta/**", "glob:**/.git/**"]
}}}
```

CLI-эквивалент: `--deny-path '_meta/**'` (повторяемый, объединяется с
конфигом, как остальные списки).

Решения по семантике:

- **Словарь паттернов — тот же, что у `allow_bash`** (`'prefix'`,
  `exact:`, `glob:`, `regex:`). Один словарь на всю фичу; оператору не
  нужно держать в голове два.
- **Deny выигрывает у allow безусловно.** Denylist проверяется после того,
  как allowlist уже пропустил вызов, и отменяет пропуск.
- **Применяется к каждому вызову тула, несущему путь**, а не к
  перечисленному набору тулов. Новый тул с путём попадает под запрет
  автоматически — единственный вариант, при котором список не устаревает
  молча.
- **Отсутствие пути — не повод пропустить.** Тул, у которого путь не
  извлекается, при непустом `deny_paths` отклоняется. Deny — безопасное
  направление, ровно как в `allowsRequest` для bash без читаемой команды
  (`runallowlist.go:118-124`).

Условие честности формулируем в документации явно и один раз:
`deny_paths` — настоящая граница **только когда недостижим интерпретатор**
(нет ни одного `--allow-bash`, либо разрешены только неинтерпретирующие
команды). Если bash разрешён — это guard rail против опечатки, не граница
безопасности. Термины берём из §4.3 исходного документа: они точные.

### 3.2. `session_created` + `--require-existing-session`

Худший класс отказа из наблюдавшихся: движок получает валидный
`exit_reason: end_turn` и осмысленный `final_text`, при этом разговор
начался с нуля. Закрываем с двух сторон.

**Поле конверта** — наблюдаемость:

```json
{ "session_id": "...", "session_created": false, ... }
```

Без `omitempty`. Это осознанно: `omitempty` на `bool` прячет `false`, и
потребитель не отличит «сессия продолжена» от «эта версия rush поля не
знает». Та же дисциплина, что уже применена к `CacheHitRatio`
(`app_run_result.go:135`) — поле контракта, на котором потребитель ветвится,
присутствует всегда.

**Флаг** — предотвращение: `--require-existing-session` даёт жёсткую
ошибку вместо создания, **до** первого потраченного токена. Проверка
встаёт в `run.go:697-701`, где сейчас происходит молчаливый провал.

Оба нужны, они решают разные задачи. Поле сообщает постфактум — к этому
моменту токены уже потрачены и узел уже ответил с амнезией. Флаг не даёт
потратить. Для персистентного дерева естественный режим: первое
пробуждение узла — без флага, все последующие — с флагом (факт «узел уже
будили» лежит в паспорте).

**Сопутствующее предупреждение, не требующее кода.** `--data-dir`
закрепляет хранилище, но ID сессий в нём — плоское глобальное
пространство имён. Два узла дерева, оба вызывающие `--session "review"`,
разделят одну память. При общем `--data-dir` идентификаторы обязаны
включать путь/uuid узла.

### 3.3. `cost_basis` — и поправка к постановке §3.3

Здесь исходный документ ставит верный диагноз симптому и неверный —
причине.

`internal/message/usage.go:48-51`, комментарий к полю, дословно:

> `CostUSD` is this message's own cost contribution, computed with the same
> four-tier formula as the session total. **Zero for flat-rate models and
> for every local CLI model (they carry no prices at all).**

Стоимость считается четырёхтарифной формулой по `CatwalkCfg.CostPer1M*`
(`internal/agent/agent_title.go:264-267`, `agent_cache_keepalive.go:390-393`).
Если все четыре цены нулевые — цена структурно нулевая при любом числе
токенов.

Исследование в исходном документе шло через **z.ai coding plan**
(`https://api.z.ai/api/coding/paas/v4`) — подписку с фиксированной платой.
Для неё маржинальной цены вызова **не существует**. Ноль здесь не «не
умеем посчитать» и не «бесплатно» — это «величина не определена для данного
тарифа». Никакая доработка rush не превратит его в настоящее число.

Отсюда два следствия — одно для нас, одно для `agent-tree.js`.

**Для rush: добавляем `cost_basis`, не трогая `cost_usd`.**

```json
"usage": {
  "delta_cost_usd": 0,
  "cost_basis": "unpriced",
  "session": { "cost_usd": 0, "cost_basis": "unpriced", ... }
}
```

- Значения: `"priced"` — каталог модели несёт ненулевые цены, число
  настоящее; `"unpriced"` — цен нет, число читать нельзя.
- **`cost_usd` остаётся числом.** Структура помечена
  «Wire-stable: fields here are part of the public contract for wrapper
  scripts» (`app_run_result.go:19-21`); превращение в nullable сломает
  существующих потребителей. Исходный документ и просил дополнительный
  флаг, а не смену типа — это совпадает.
- **Агрегация деградирует к худшему**: если хоть один вклад `unpriced`,
  сумма `unpriced`. Точно та же дисциплина, что уже применена к
  `mergeCacheSupport` и к «липкому» `Estimated` (`usage.go:113-137`).
- **Значения `"flat_rate"` не вводим.** Отличить фиксированный тариф от
  отсутствующих цен мы не можем — оба выглядят как четыре нуля.
  Ввести различение, которое не вычисляется, — та же ошибка, что и
  сфабрикованный ноль, только на уровень выше.

Прецедент внутри той же структуры уже есть, и на него стоит опираться:
`CacheHitRatio *float64` документирован как «null когда не может быть
заявлен… потребители ОБЯЗАНЫ ветвиться на null, а не читать 0 —
сфабрикованный ноль неотличим от настоящего промаха кеша»
(`app_run_result.go:131-135`). Аргумент §3.3 исходного документа — это тот
же аргумент; мы просто распространяем уже принятую здесь дисциплину на
соседнее поле.

**Для `agent-tree.js`: бюджетный контур надо строить на токенах, не на
деньгах.** `budget_usd` / `subtreeCost` / отказ по `spent >= budget`
неработоспособны на тарифе с фиксированной платой не из-за пробела в rush,
а по природе тарифа. `usage.session.total_tokens` реален у каждого
провайдера, включая flat-rate.

Готовый механизм на стороне rush уже есть и менять его не нужно:
`rush run --max-tokens 100k` — runaway-protection с сохранением в бюджет
сессии, наравне с `--max-cost` (`internal/cmd/run.go:316-318`).
`rush sessions show <id>` отображает потребление против бюджета. Контур
`agent-tree` ложится на это напрямую заменой единицы измерения.

### 3.4. Фактически использованная модель

Данные уже вычисляются и выбрасываются. `message.UsageReport.ByModel` —
это `[]ModelUsage`, где каждый элемент несёт `Usage.Provider` и
`Usage.Model` (`internal/message/usage.go:54-58`). `buildSessionUsageInfo`
читает эту карту ровно для проверки на пустоту
(`if len(report.ByModel) == 0`, `app_run_result.go:152`) и дальше берёт
только `report.Total()`, теряя разбивку.

Добавляем два поля, потому что они отвечают на разные вопросы.

**`usage.session.by_model[]` — правда.** Что реально произвело сообщения
за всё время сессии: `{provider, model, messages, input_tokens,
output_tokens, total_tokens, cost_usd, cost_basis, cache_support,
estimated}`. Комментарий к `TokenUsage.Provider` объясняет, почему это
нужно именно так: «сессия может сменить модель посреди разговора, а
суб-агент может работать на модели, отличной от родительской, поэтому
текущий выбор сессии — небезопасная замена при агрегации».

**`model_selection` верхнего уровня — намерение.** Что этот запуск
разрешил и запросил: `{role, provider, model, effort}`. Доступно бесплатно
в точке, где `--role` разворачивается в слот (`run.go:713-718`).

Оба нужны для сценария из §3.4 исходного документа. Страх там
сформулирован точно: «`--role smart` указывает на изменяемый глобальный
слот… кто-то может сменить, что стоит за `smart`, и узел этого не узнает».
Заметить подмену позволяет именно сопоставление намерения (какой слот
запрошен и во что он развернулся сейчас) с правдой (что реально
отработало). По отдельности ни то, ни другое подмену слота не показывает.

### 3.5. `tool_calls[].paths` для мутирующих тулов

Расширяем `toolCallStat` полем `paths []string`, заполняемым для `edit`,
`write`, `multiedit`.

Границы решения:

- **Только мутирующие тулы в первой версии.** Заявление вида «я правил
  только `foo/`» проверяется по фактам записи; объём при этом ограничен
  естественно (правок за ход единицы, а не сотни).
- **Пути чтения не включаем.** `grep`/`glob`/`view` дают объём другого
  порядка, и конверт перестаёт быть обозримым.
- **Ограничение сверху** — 100 путей на тул, с флагом
  `paths_truncated: true`. Молчаливое усечение читалось бы как «это всё,
  что было».

**Учёт чтений уже возможен без изменений в rush** — и это лучший
механизм, чем конверт. У rush есть хуки `PreToolUse`, и в окружение хука
передаётся `RUSH_TOOL_INPUT_FILE_PATH` — значение `file_path` из аргументов
тула. Роутер может писать полный журнал обращений (включая чтения `_meta/`)
вне канала агента, тем самым вне его влияния. Для §4.1 исходного документа
это точнее конверта: журнал, который агент не формирует, подделать сложнее,
чем поле, которое едет через его же вызов.

### 3.6. `--system-prompt-ephemeral`

Булев модификатор к уже существующим `--system-prompt` /
`--system-prompt-file`: промпт применяется к текущему ходу и **не**
вызывает `Sessions.UpdateSystemPrompt`. Ошибка, если ни один из двух
флагов не передан.

Модификатором, а не третьим флагом — чтобы не удваивать каждый из двух
существующих в `-ephemeral`-вариант.

**Приоритет низкий, и это осознанно.** Исходный документ и сам отмечает,
что текущее поведение работает: `agent-tree.js` пересчитывает промпт на
каждом пробуждении и передаёт его каждый раз, поэтому сохранённое значение
всегда перезаписывается свежим. Возражение — к тому, что вызов *пишет
состояние*, а не к результату. Стоимость дефекта: лишняя запись в БД на
пробуждение плюс устаревший промпт в сессии между пробуждениями. Чинить
стоит, срочности нет.

## 4. Чего не делаем

### 4.1. Песочницу (`--sandbox <profile>`) — не будет

Пункт №1 исходного списка. Отказ, с тремя причинами.

**Кросс-платформенность не позволяет сделать это честно.** Настоящая
песочница специфична для ОС: mount namespaces / bind mounts на Linux,
`sandbox-exec` (deprecated) или Endpoint Security на macOS, на Windows —
AppContainer и job-объекты с частичной виртуализацией ФС. Windows для
этого форка не второстепенная платформа: вся история с всплывающими
консольными окнами (`CREATE_NO_WINDOW`, `internal/platform/`) — про то,
сколько стоит там честная работа с процессами. Флаг `--sandbox`, который
на Linux настоящий, а на Windows декоративный, хуже отсутствующего: он
переносит ложную уверенность через границу платформы, а вывод самого
исходного документа — целиться в обнаружимость, а не в видимость защиты.

**Это не слой rush.** Конструирование файлового представления процесса —
задача вызывающего: контейнер, `bwrap`, job-объект, ВМ. rush принимает
`--cwd` и `--data-dir` и корректно работает внутри любого из них. Это
композиция, а не пробел.

**Большинству узлов дерева песочница не нужна** — по выводу §4.2 самого
исходного документа. `reader`/`writer` получают настоящую границу из
deny-by-default плюс `deny_paths` (3.1). OS-изоляция требуется только
`builder`, а для него §4.3 уже сознательно приняла цену.

Итог: rush не растит песочницу, но растит то, что делает
не-`builder`-классы действительно исполнимыми, и остаётся композируемым
внутри любой песочницы, выбранной вызывающим.

### 4.2. Не переносим механику tamper-evidence в rush

§4.1 исходного документа (хеш предыдущего состояния в записях
`dialog.md` / `passport.json`, разрыв цепочки виден роутеру) — правильный
вывод и правильный слой. Это модель данных `agent-tree`, а не rush: цепочку
пишет и проверяет движок, rush в ней не участвует. Со стороны rush
единственное, что для этого нужно, — механизм наблюдения, и он уже есть
(хуки `PreToolUse`, см. 3.5).

## 5. Порядок работ

Ранжировано по тому, какой наблюдавшийся отказ закрывает.

| # | Изменение | Закрывает | Оценка |
|---|---|---|---|
| 1 | `run.deny_paths` + `--deny-path` | §2.1 в рамках `reader`/`writer`; делает классы §4.2 исполнимыми | средняя |
| 2 | `session_created` + `--require-existing-session` | §2.2 — худший класс отказа | малая |
| 3 | `usage.session.by_model[]` + `model_selection` | §3.4; данные уже посчитаны | малая |
| 4 | `cost_basis` | §3.3, в переформулированном виде | малая |
| 5 | `tool_calls[].paths` | §3.6 | средняя |
| 6 | `--system-prompt-ephemeral` | §3.5 | малая |

Каждый пункт — отдельный коммит с тестами; пункты 2-4 и 6 не связаны между
собой и могут идти в любом порядке. Пункт 1 затрагивает
`internal/permission/runallowlist.go` и требует расширения существующего
набора тестов на allowlist, а не нового файла.

**Не входит в этот план:** песочница (4.1), tamper-evidence (4.2),
что-либо в `agent-tree.js`.

## 6. Что уже работает и менять не нужно

Сводка существующих механизмов, отвечающих на части исходного документа
без изменений кода. Их стоит проверить до того, как ждать доработок.

| Потребность | Готовый механизм |
|---|---|
| Бюджет узла и поддерева | `--max-tokens` (в токенах, а не в деньгах — см. 3.3) |
| Классы способностей `reader`/`writer` | `--restrict-run` + `--allow-tool` без `--allow-bash`; либо `options.disabled_tools` |
| Учёт чтений, в том числе `_meta/` | хуки `PreToolUse`, `RUSH_TOOL_INPUT_FILE_PATH` |
| Хранилище сессий вне cwd | `--data-dir` (persistent-флаг рута) |
| Guard rails против опечатки в bash | compound-guard в `allow_bash` — реализует рекомендацию §4.3 |
| Защита файлов, куда пишет сам оркестратор | `RUSH_FORBID_WRITES` |

## 7. Итог одним абзацем

Из шести запросов исходного документа делаем пять, отказываемся от одного
(песочница) и добавляем седьмой, которого в списке не было и который
важнее остальных — путевой скоуп для `--allow-tool`. Главная содержательная
поправка: `--restrict-run` не относится к тому же разряду, что
`--allowedTools`, поэтому обход через `node -e` к rush не применяется, и
классы `reader`/`writer` из §4.2 на rush-бэкенде достижимы уже сегодня —
им не хватает только запрета по путям. Вторая поправка: нулевая стоимость
на тарифе с фиксированной платой не чинится вообще, поэтому бюджетный
контур `agent-tree` следует переводить на токены; rush отвечает за то,
чтобы ноль перестал выглядеть как измеренная величина, а не за то, чтобы
сделать его настоящим числом.
