Ядро дизайна (принято ревью): каждая сессия пишет стоимость ТОЛЬКО в свою
строку и ТОЛЬКО прибавлением; «с детьми» — сумма по дереву при чтении; окно
прогона — разность монотонной суммы. Убираемый класс дефектов: перенос
«ребёнок → родитель» дельтами с водяным знаком `parent_cost_accounted` из
нескольких мест (находки R4C-2, R5C-3, R6C-3, R7A-1, R8A-4, R8B-3 — см. §8).

## §Р Обязательные решения (кратко, детали в §2–§7)

1. `cost_self` строго монотонен (только `+`, писатель один — `IncrementCost`);
   `decrementCost`/`owedChildCost` удаляются. `sessions reset` пишет ОДНУ
   колонку одним UPDATE: `cost_base(X) = subtree_spent(X)`. Бюджет(X) =
   `subtree_spent(X) − cost_base(X)` (зажим ≥0 при чтении, P3 — §2.3).
   Окно прогона = разность `subtree_spent`, сбросы его не трогают.
2. Ребро дерева стоимости — только делегации: флаг пишется один раз в
   `CreateTaskSession` (`internal/session/session_lifecycle.go:52`);
   `sessions fork --child` (`internal/session/session_fork.go:107`) —
   собственный корень стоимости. ОДНО определение дерева: один запрос в
   `internal/db/sql/sessions.sql` + один Go-метод; рекурсивный CTE с `UNION`
   по id (на цикле завершается, узел считается один раз; НЕ
   `UNION ALL`+depth). Три сегодняшних определения дерева в стоимостном коде
   сводятся к нему (§2.2).
3. Backfill — формула §5 (s — только по делегационным детям; подзапрос читает
   ИСХОДНЫЙ `cost`; шаг `cost = cost_self` недопустим) + тест-инвариант на
   каждый узел.
4. Миграция M1 — только аддитивная: `cost_self`, `cost_base`, флаг делегации +
   backfill; `cost` и `parent_cost_accounted` не трогаются (путь отката;
   goose v3.27.1 у старого бинаря молча игнорирует неизвестные версии, Down
   старый бинарь не запустит). Новый бинарь `parent_cost_accounted` не пишет
   никогда; `cost` пишет только как зеркало своих дельт в том же UPDATE, что
   `cost_self`, и НИКТО его не читает (поле `Session.Cost` переименовать в
   `OwnCost`, чтобы компилятор перечислил читателей). Предусловие перехода:
   нет живых старых процессов rush на БД. Повторный апгрейд после отката не
   поддерживается. Удаление зеркала и водяного знака — отдельная миграция вне
   этой задачи.
5. Все читатели стоимости — на одну функцию бюджета/окна (§3); после
   переименования компилятор перечисляет оставшихся.
6. `--max-tokens` остаётся по строке корня (prompt/completion — снимки, а не
   накопленные счётчики, `internal/cmd/sessions_cost.go:32-34`): сумма по
   дереву бессмысленна.
7. Ответы бывших открытых вопросов §5 — зафиксированы в §7 (один релиз;
   `cost_usd` = бюджет поддерева, добавляется `own_cost_usd`; `--max-cost` =
   бюджет корня; для `RUSH_COST_USD` при kill -9 ничего не делаем; ни колонки,
   ни таблицы pre-migration).
8. Активность поддерева (`--continue`, порядок `sessions list`,
   `sessions cost --since/--by day`) — тоже запрос (max `updated_at` по тому
   же дереву), НЕ запись `updated_at` родителя из ребёнка (§4).

## 2. Модель

### 2.1 Величины

- **`cost_self(X)`** — монотонная сумма СВОИХ трат узла X: шаги хода,
  компакция, title, keep-alive. Единственный писатель — `IncrementCost` /
  `IncrementCostIfUnderMax` (W1/W2). Никогда не уменьшается, никогда не
  пишется ничем другим.
- **`cost_base(X)`** — база бюджета: значение `subtree_spent(X)` на момент
  последнего `sessions reset X`. Писатели — только reset и миграция.
- **`subtree_spent(X)`** — `SUM(cost_self)` по дереву делегаций от X (§2.2).
  Чистое чтение, всегда актуально.
- **Бюджет(X)** = `max(subtree_spent(X) − cost_base(X), 0)` — «с детьми, с
  последнего сброса» ( сегодняшний смысл показываемой стоимости).
- **Окно прогона** = `subtree_spent(корень, выход) − subtree_spent(корень,
  claim)`, каждая величина читается в одной read-транзакции-снимке. Сбросы
  (`cost_base`) окно не трогают — сброс в середине прогона не «съедает»
  окно (в отличие от семантики бюджета).
- **`--max-cost`** = бюджет корня (поддерево с последнего `sessions reset`),
  не окно прогона; проверяется и в `enforceRunawayCaps`, и в `stopError`/
  `capError`, и в предикате W2 — везде один запрос.
- **`--max-tokens`** = по строке корня, БЕЗ дерева: prompt/completion токены —
  снимки-счётчики последнего хода, а не накопление
  (`internal/cmd/sessions_cost.go:32-34`), сумма по дереву бессмысленна.
- **Удалённый/уплывший ребёнок** может увести бюджет в минус (base посчитан
  раньше, spent стал меньше): зажим `max(…, 0)` при ЧТЕНИИ; отрицательные
  значения в БД не пишутся никогда. Классификация: P3, задокументировать
  (`sessions cost` показывает 0, диагностика по `own_cost_usd`/логу reset).

### 2.2 Дерево стоимости

Ребро — только делегация: флаг `cost_parent_id` (или `is_delegation`;
выбор имени — за реализацией, дальше `cost_parent_id`) пишется РОВНО ОДИН раз
при создании задачи — в `CreateTaskSession`
(`internal/session/session_lifecycle.go:52`). `sessions fork --child`
(`internal/session/session_fork.go:107`) ставит `parent_session_id`, но НЕ
флаг: fork — собственный корень стоимости (сегодня его стоимость и так не
переносится и в `sessions cost` скрыта — поведение сохранено и задокументировано).

ОДНО определение дерева: один запрос в `internal/db/sql/sessions.sql`
(рекурсивный CTE с `UNION` по id — на цикле в данных завершается и считает
узел один раз; НЕ `UNION ALL`+depth, как в `internal/db/sql/call_tree_activity.sql:25-32`)
+ один Go-метод на `session.Service` (`SubtreeSpent`, `SubtreeUpdatedAt`, §4).
Сегодняшние три определения дерева в стоимостном коде сводятся к нему:

- обход глубиной 16 в `chargeRunningChildren`

- `parent_session_id` без флага, depth<511, `UNION ALL`
  (`call_tree_activity.sql:25-32`) — не трогаем (это активность сообщений,
  не деньги), но стоимостные использования parent_session_id-напрямую

- CTE редакции 1 — заменён единым.

Индексы `(parent_session_id, …)` уже есть (`internal/db/migrations/20260828000001_*.sql:53-58`);
для флага при необходимости — составной индекс той же миграцией M1.

### 2.3 Свойства, из которых находки невыразимы

- R4C-2 / R5C-3 / R6C-3 (трата ребёнка между ходами / на отмене / Drain-ходы
  делегированного ребёнка): «с детьми» читается запросом в момент чтения — не
  существует момента «ещё не перенесено» и момента переноса вообще.
- R7A-1 / R8A-4 (reset ломал монотонность и следующий перенос): `cost_self`
  монотонен физически (нет писателя с уменьшением), `cost_base` — отдельная
  колонка; сброс не меняет ни `cost_self`, ни окно прогона; водяной знак
  удалён.
- R8B-3 (cap не видит цепочку во время ожидания): `stopError`/`capError`/
  `enforceRunawayCaps` выполняют один и тот же запрос бюджета; ребёнок платит
  в свою строку мгновенно.

## 3. Backfill (миграция M1, решение 3)

s — только по ДЕЛЕГАЦИОННЫМ детям C (флаг из W14; строки до миграции — по
схеме id = `msg$$call`); подзапрос читает ИСХОДНЫЙ `cost` (шаг
`cost = cost_self` с последующим чтением — недопустим):

```
s(C)         = CASE WHEN C.cost >= C.parent_cost_accounted
                    THEN C.parent_cost_accounted ELSE 0 END   -- = C.cost − owedChildCost(C)
cost_self(X) = max(X.cost − COALESCE(Σ_{C∈delchildren(X)} s(C), 0), 0)
e(X)         = max(COALESCE(Σ_{C∈delchildren(X)} s(C), 0) − X.cost, 0)
cost_base(X) = Σ_{Y ∈ subtree(X)} e(Y)
```

Смысл: `e(X)` — стоимость, которая «застряла» в X сверх его собственных трат
(перенесённая внутрь от детей, которых при новом дереве к нему не относят или
которые уже посчитаны сами). Она и становится базой бюджета — иначе после
перехода бюджет занижается/завышается на уже показанные суммы.

Тест-инвариант для КАЖДОГО узла X после backfill:

```
Σ_{Y∈subtree(X)} cost_self(Y) − cost_base(X)  ==  X.cost + Σ_{D∈desc(X)} owedChildCost(D)
```

Фикстура (все случаи в одной БД): частичный перенос (`accounted < cost`),
внук, legacy-строка `cost < accounted` (s(C)=0 ветка), сброшенный родитель,
ребёнок, сброшенный ПОСЛЕ переноса (`cost = accounted = 0`).

Точность: атрибуция «своего» у сброшенных узлов приблизительна (сброс сегодня
зануляет и `cost`, и знак — делить нельзя); БЮДЖЕТ точен — инвариант выше
гарантирует равенство старой и новой «с детьми» величины на каждом узле.
Сказать в документации релиза.

## 5. Миграция (решение 4)

**M1 — единственная миграция этой задачи, ТОЛЬКО аддитивная:**
- `ALTER TABLE sessions ADD COLUMN cost_self REAL NOT NULL DEFAULT 0;`
- `ALTER TABLE sessions ADD COLUMN cost_base REAL NOT NULL DEFAULT 0;`
- колонка флага делегации (`cost_parent_id`) + индекс при необходимости;
- backfill §3 одним проходом (батчами по `rowid`, если объём потребует).

**НЕ трогается:** `cost`, `parent_cost_accounted`. Это и есть путь отката:
goose v3.27.1 у старого бинаря молча игнорирует неизвестные ему версии
миграций и не запустит Down-SQL; старый бинарь продолжает работать на
`cost`/`parent_cost_accounted`, как будто M1 не было.

**Новый бинарь (тот же релиз, что M1 и переключение читателей, §7.1):**
- `parent_cost_accounted` не пишет НИКОГДА;
- `cost` пишет только как зеркало своих дельт — тот же UPDATE, что `cost_self`
  (W1/W2), чтобы старый бинарь при вынужденном соседстве видел правдоподобную
  свою строку; НИКТО в новом коде `cost` не читает: поле `Session.Cost`
  переименовывается в `OwnCost` — компилятор перечисляет всех читателей (§1.2);
- `sessions reset` → один UPDATE `cost_base(X) = subtree_spent(X)`.

**Предусловие перехода:** на БД нет живых старых процессов rush (relnotes;
если дёшево — проверка по `session_drivers`/lock-файлам при старте, отказ
миграции при живых).

**Down:** `DROP COLUMN` трёх новых колонок. **Повторный апгрейд после
отката НЕ поддерживается** — траты, случившиеся на старом бинаре после
отката, обратно не расклеиваются (написать в relnotes).

**Позже, вне этой задачи:** отдельная миграция удаляет зеркало `cost` и
`parent_cost_accounted` (когда пройдёт достаточный окно даунгрейда).

## 7. Решённые вопросы (бывшие открытые, решение 7)

1. **M1 и переключение — ОДИН релиз:** `IncrementCost` уже пишет `cost_self`,
   читатели на дереве, W7–W11 и стоимостная часть `queuedMark` удалены.
   Известная потеря: траты между backfill и первым писателем `cost_self`
   пропадают навсегда — окно стремится к нулю в пределах одного запуска.
2. **Контракт:** `cost_usd` сохраняет смысл (бюджет поддерева с последнего
   сброса), добавляется `own_cost_usd`; web `Session.Cost` не показывает —
   синхронный web-релиз не нужен.
3. **`--max-cost`** = бюджет корня (не окно прогона).
4. **`RUSH_COST_USD` при kill -9:** ничего не делать (окно не фиксируется —
   честно отсутствует).
5. **Pre-migration копия `cost`:** ни колонки, ни таблицы — исходный `cost`
   не меняется (см. §5).

## 9. Остаточные риски (без открытых вопросов)

- Траты между backfill и первым писателем `cost_self` теряются (§7.1) —
  принято, окно в пределах одного запуска.
- Повторный апгрейд после отката не поддерживается (§5).
- Бюджет может «уехать» при удалении/потере узла дерева — зажим при чтении,
  P3 (§2.1).
- Атрибуция «своего» у сброшенных узлов приблизительна (§3) — бюджет точен.
