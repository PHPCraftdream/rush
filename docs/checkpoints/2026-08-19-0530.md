# Checkpoint — 2026-08-19 05:30 [release-blockers-cleared]

## Session summary

Two operator requests came in mid-session and both are finished: the GLM
short codes `glm5_2`/`glm5_1`/`glm5` are gone (5.3 and 5-turbo stay, 4.x
untouched), and the model slots are renamed `large`/`small` → `smart`/`fast`
hard, with no backwards compatibility, which the operator chose explicitly
over an alias-reading loader. The rename touched 185 files: config key, CLI
flags, HTTP/WebSocket fields, six database columns, the React UI, the
Playwright selectors, the generated Claude slash-command, and the text
`crush_info` gives an agent when it has to pick a slot. `resolveModelRole`
collapsed to a plain validating parse — there is nothing left to translate,
which was the point.

Go identifiers were renamed **lexically**, not textually: a small `go/scanner`
tool patching only IDENT tokens by exact whole-identifier match (1677 renames,
134 files), because this repository's comments are full of "large thinking
budgets" and "a small side LLM call". Size-flavoured identifiers were
classified out by hand. `DefaultLargeModelID` had to be reverted — it belongs
to the external `catwalk.Provider`, and a token-level tool cannot tell it from
one of ours; the build failure is how it was found.

**Running the binary caught four things the test suite, golangci-lint and
`pnpm typecheck` all missed** — each a slot name inside a string the compiler
does not read. The worst was a wire mismatch: Go still sent
`recentLargeModels` while the web store had moved to `recentSmartModels`, a
silent runtime break that typechecks fine on both sides independently.

Then the four remaining release blockers from the 2026-08-18 review, in the
order that review recommended. All four are fixed, each with a test verified
to fail without its own half of the fix. Three of them were the same defect
wearing different clothes: `crush run` telling the operator work had completed
when it had not — because a lease was mistaken for an execution, because a
failed commit returned nil, and because a timeout could not reach a
continuation that had already started.

**A genuinely new bug surfaced while adding one query: sqlc v1.30.0 silently
corrupts generated SQL when a `.sql` comment contains a multi-byte character.**
Two em-dashes truncated a query's tail by exactly their byte overhead; a longer
non-ASCII block corrupted an unrelated query at the top of the same file into
invalid SQL. `sqlc generate` exits 0 and the Go compiles — it fails at Prepare
time, i.e. at process start. Bisected directly (CASE-vs-IIF, whitespace,
RETURNING shape and file position all ruled out first). Every committed `.sql`
was ASCII by luck; the pre-push hook now enforces it. The guard itself took
three attempts — two earlier versions would have shipped as checks that do
nothing, and only testing against a deliberately violating tree caught them.

## Decisions

- **The slot rename is hard, with no alias fallback.** Operator's explicit
  choice. Existing `crush.json` files stop applying; the operator's own global
  and workspace configs were migrated with backups and verified
  programmatically to differ only in the two key names.
- **Identifier renames go through a lexer, not a regex.** Comments and string
  literals were swept separately and by hand, because the two meanings of
  "large" in this codebase are not mechanically distinguishable.
- **A failed commit is not nacked.** Nacking re-runs a turn whose side effects
  already landed, immediately. Leaving the row leased costs one lease TTL but
  charges an attempt, so a persistently failing commit dead-letters instead of
  looping.
- **Session admission is exclusive, not a refcount.** One execution per session
  per pump instance was always the intended invariant; the drain was bypassing
  it, not implementing a second legitimate mode.
- **`internal/db/sql/` is ASCII-only, enforced.** Not a style rule — a
  correctness one.

## Open questions

- **Playwright e2e has not been run** since the `data-test-id` values changed
  (`model-selector-large` → `-smart`). The specs were updated with them, but
  the suite has not been executed.
- **The sqlc bug has not been reported upstream**, and the committed
  `*.sql.go` files are not verified against a fresh `sqlc generate` in CI —
  the ASCII guard closes the known trigger, not the general drift.
- **Two sub-agent defects from an earlier live smoke test remain unfiled**: a
  sub-agent told to append overwrote a file and reported "+2 lines", and a
  write to a non-existent path reported success.
- One residual is documented rather than fixed: if the background tick wins the
  lease race and THEN finds the session externally owned, the drain still
  reports `drained=true`. Closing it needs an outcome handoff between the two
  dispatch paths.
