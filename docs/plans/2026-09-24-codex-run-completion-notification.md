# План: `rush run --codex-thread-id`

Статус: план, без реализации. Связан с [планом источников скиллов](2026-09-24-skill-source-variants.md).

## Цель и обнаруженный разрыв

`rush run --codex-thread-id <thread-id>` после каждой начатой CLI попытки посылает в указанный поток Codex одно осмысленное сообщение: успех, ошибка, отмена или остановка с вопросом. Оповещение должно работать без shell экранирования текста сообщения и не подменять результат самого запуска.

Сейчас `--on-finish` передаёт строку в `cmd /c` на Windows или `bash -c` на Unix (`internal/app/run_on_finish.go`). Хук регистрируется лишь после создания сессии в `ExecuteRun` (`internal/app/app_run.go`) и выполняется до возврата из него. Итоговый JSON печатается позже в `RunNonInteractive`. Поэтому хук не охватывает некоторые ранние ошибки и может сообщить о завершении до записи результата. Установленный Codex скилл использует `--on-finish 'codex queue ...'` как временный обходной путь.

Локальный `codex queue --help` подтверждает интерфейс `codex queue --thread <THREAD> --message <TEXT>`; `--thread` принимает UUID или точное имя. Новый флаг Rush принимает именно ID потока; значение передаётся явно, без автоматического чтения `CODEX_THREAD_ID` внутри Rush. Скилл Codex может прочитать эту переменную и передать её флагу.

## Место в жизненном цикле

1. Зарегистрировать строковый флаг в `internal/cmd/run.go`. Пустое значение оставляет поведение прежним; непустое проверить при входе в `RunE` (формат UUID, отсутствие управляющих символов) до загрузки конфигурации.
2. Установить в `RunE` один отложенный обработчик завершения сразу после чтения валидного флага. Он видит именованную возвращаемую ошибку и, когда доступен, типизированный `app.RunResult`. Это охватывает ошибки валидации других флагов, `setupApp`, отсутствующего провайдера, запуска модели и записи итогового JSON. Ошибки разбора флагов самим Cobra до входа в `RunE` находятся вне этого контракта.
3. Дать CLI доступ к `RunResult`, не парся собственный stdout: выделить из `RunNonInteractive` вариант, возвращающий `(*RunResult, error)` после рендера, сохранив старую сигнатуру как совместимую обёртку. Уведомлять после записи JSON и после `a.Shutdown()`; порядок `defer` зафиксировать тестом. При ошибке до создания сессии использовать запрошенный `--session`, если он был, иначе явно сообщить «сессия не началась».
4. Существующий `--on-finish` оставить независимым механизмом. При одновременном использовании обоих флагов оба действия выполняются; сгенерированный Codex скилл должен использовать только новый флаг, чтобы не получать дубликаты.
5. Для recoverable panic внутри `RunE` отправить сообщение об ошибке и затем повторно вызвать panic, сохранив текущую диагностику. `os.Exit`, принудительное завершение ОС и потерю питания невозможно гарантированно уведомить из того же процесса; это явная граница контракта.

## Содержимое сообщения

Сообщение начинается с короткого машинно узнаваемого маркера `rush_done:<session>` (или `rush_done:unstarted`). Дальше одна строка с состоянием, ID сессии и коротким содержательным итогом:

- Успех: `exit_reason` и ограниченный по длине первый содержательный фрагмент `final_text`.
- Ошибка или отмена: причина из `RunResult.Error` либо возвращённой ошибки; отсутствие результата обозначить прямо.
- `awaiting_answer`: отдельное состояние с кратким вопросом, без ложной отметки об успешном выполнении. `queued`: сообщить, что эта CLI попытка не исполнила агентский ход.

Ограничить длину по Unicode символам, убрать управляющие символы и переводы строк, не включать полный промпт, переменные окружения или весь вывод агента. Кавычки и знаки препинания в оставшемся тексте сохраняются. Маркер служит сигналом продолжить проверку; Codex должен подтвердить завершение процесса и прочитать полный результат отдельно.

## Доставка без shell

1. Вызвать `codex queue` как дочерний процесс с отдельными аргументами: `queue`, `--thread`, ID, `--message`, **одно** значение сообщения. Не собирать строку команды и не передавать её в `cmd /c`, `bash -c` или PowerShell. Тогда одинарные/двойные кавычки, пробелы, `&`, `%`, `$()` и Unicode не требуют ручного экранирования.
2. Использовать `platform.Command` и отдельный короткий timeout с новым контекстом: контекст агентского запуска к моменту уведомления может быть отменён. На Windows не передавать свободный текст через npm `.cmd` shim, который снова вводит shell. Резолвер должен предпочесть нативный `codex.exe`; при npm установке допустимо запускать `node` с найденным `@openai/codex/bin/codex.js` и отдельными argv. Если безопасный исполняемый путь не найден, вернуть диагностическую ошибку доставки. Ограничить время работы и завершать только созданное дочернее дерево при таймауте.
3. Ошибка `codex queue` выводится в stderr с исходной причиной и не меняет exit code успешного/неуспешного `rush run`. Не делать слепой повторной отправки: после неопределённого сбоя это создаст дубли. Успешная доставка означает принятие сообщения CLI, а не гарантирует пробуждение выгруженного потока Codex.

## Тесты и критерии готовности

- Внедряемый исполнитель процесса принимает путь и `[]string`; тест проверяет точные argv для текста с `"`, `'`, пробелами, `&`, `%`, `$()`, обратными косыми, Unicode и переводом строки. Никакого исполнения текста оболочкой.
- Табличные тесты сообщений: успех, ошибка агента, ранняя ошибка до сессии, JSON encoding error, отмена, `awaiting_answer`, `queued`, пустой `final_text`, очень длинный текст. Проверить один маркер и одну отправку на попытку.
- Тест `RunE` с подменённым исполнителем подтверждает: без флага отправки нет; при ошибке отправка есть; итоговый stdout уже записан к моменту отправки; ошибка доставки не скрывает первоначальную ошибку и не превращает успешный ход в ошибку.
- Отдельно проверить разрешение исполняемого файла на Windows (нативный бинарник и npm shim через `node`) и на Unix, timeout и отсутствие оставшегося дочернего процесса. Реальный поток Codex не использовать в автоматических тестах.
- Обновить `rush run --help` и после готовности первого плана сгенерировать Codex скилл с `--codex-thread-id`. Готово, когда успешный и ошибочный запуск посылают ровно одно осмысленное сообщение с неизменёнными кавычками и исходным кодом завершения Rush.
