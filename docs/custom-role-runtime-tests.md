These tests were **not run locally** for this documentation-only update; CI verification is performed by the main agent. A test's presence in this list is not evidence that it passed.

## Explicit coverage gaps

- There is no assertion here of a real **process restart followed by custom-role dispatch**. `TestCustomRoleContractDurableCallOptionsRoundTrip` is JSON encode/decode; session-store tests recreate a service over the same test DB connection. Do not describe those as a restart/reopen integration test.
- Role matching tests prove pattern semantics; `TestBatchExecutorRejectsRoleForbiddenGenericToolBeforeLeaf` proves a batch generic `bash` leaf is blocked before its callback. No listed focused test asserts the filtering/dispatch wrappers against a real custom-role tool set, including direct denial of `ask_question`, `await_tasks`, and individual batch-control tools. `TestResolveRoleContractPreservesEmptyInheritedDenyAll` checks the exported predicate for one empty inherited group, but the named coverage does not demonstrate a dispatched tool under multiple inherited groups. Treat tool visibility/dispatch as a coverage gap, not a proven end-to-end guarantee.
- `TestCustomRoleModelResolveUsesPinnedConfigWithoutChangingAuthority` checks that model and prompt resolvers use the supplied configuration generation, detach mutable model fields, and preserve durable tool ceilings. `TestCustomRoleNextModelResolveFailsClosed` checks exact-name removal, incomplete profiles, and unavailable providers. `TestCustomRoleDurableContractRejectsRemovedRoleOnNextResolve` checks removal refusal after a JSON call-options round trip. These focused tests do not prove cross-process reload timing, an actual provider request after removal, or a full child-session restart; those remain integration gaps.
- The list contains app and CLI parser coverage, API run admission/backend coverage, batch admission, and API task tests for built-ins. It does not include an SDK `RunOverrides.RequestedRole` integration test, an end-to-end API `/tasks` custom-name assertion, or a completed top-level CLI provider-dispatch test.
- The schema test `TestCallOptionsSpecV3RoundTripAndV2Compatibility` asserts v3 version stamping and a non-role options round trip plus legacy v2 acceptance. `TestCustomRoleContractDurableCallOptionsRoundTrip` separately checks role-contract JSON round trip. Together they do not assert one v3 role-contract round trip plus v1/v2-without-contract compatibility and v1/v2-with-contract rejection in a single coverage set; expand coverage if that distinction is required as a release gate.
- No entries report test execution results. CI results should be recorded by the main agent; this documentation change performed no tests.
