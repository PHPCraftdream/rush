## Decisions

- Worktree topology for the disk-provider feature: chain through an accumulating intermediate branch (`disk-provider-integration`), never merge each task's worktree straight to `main` — only the final, fully-verified accumulated branch merges to `main` once #859 lands. Explicit user direction, a deliberate departure from T1–T12's "merge each task directly to main" pattern.
- Delegation mechanism switched from `/wrush` (`rush run` CLI subprocess, today's earlier pattern) to the `Agent` tool with `subagent_type: "sh"` for the disk-provider feature, per explicit user instruction.
- `DiskProvider`'s zero value (`nil`) means "use the real disk" — a deliberate INVERSION of `permission.FolderScope`'s zero-value-denies-everything, because there is no sensible "deny everything" disk, only "the real one" or a caller's substitute. Documented explicitly in `fs_provider.go` so it's not mistaken for an oversight later.
- `DiskProvider` lives in package `internal/agent/tools` (not a new leaf package) because `OSDisk`'s `Find`/`Search` need unexported `globFiles`/grep-engine code shared with the legacy `glob`/`grep` tools — moving that code out would have dragged legacy tools into this feature's scope.
- `history`/`filetracker`/`permissions.Request`/`CheckForbiddenWrite` are deliberately NOT redirected through the disk provider — they stay real-disk/real-service always. A provider only redirects raw bytes-on-disk I/O, not the operator-approval channel, the audit/undo record, or the real-disk write blacklist.
- `fs_read`'s missing `filetracker.RecordRead` call (a real pre-existing bug, found during #857's implementation) was fixed INSIDE #857 rather than deferred, since #857 was already touching every relevant line — matches this session's standing "fix flakes/bugs on the spot" rule.
- The mandatory durable-restart refusal for a disk-provider-carrying call (folded into #859, not deferred) follows T9's "refuse outright" precedent, not T12's "persist and restore" — a Go interface value cannot be serialized, so there is nothing to persist; the correct behavior is refusing to ever let such a call reach the durable queue, not silently falling back to the real disk after a restart.
- Two production commits that had been sitting uncommitted since earlier in the session (T12's actual feature diff, and the unrelated live-incident memory-leak fixes) were split into two separate, clean commits (`cec10b5d` then `1b6b2b0e`) rather than one mixed commit, keeping the fix and the feature independently revertable/bisectable.
- A stale, long-running background `go test` process (task id `b4bw4bbdr`, launched much earlier in the session, testing an already-superseded code state) was killed by specific PID rather than left running, once fresh targeted verification made it redundant.
