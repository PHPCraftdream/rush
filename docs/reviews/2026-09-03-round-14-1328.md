end-to-end style. Revert-check: reintroducing error-discarding assignment

restored.

**Делегировано через `/wrush`**, hand-merged после independent

сделанный через новую `/wrush` методологию — подтверждает что
методология работает.

**Замечание:** `FromSessionAgentCallData` теперь имеет error return,
но его doc-комментарий не явно не говорит что это "тест-only" конвертер
сейчас. Не проблема сегодня (все call sites обновлены), но если

semantics без уточнения. Minor — можно добавить одну строку в doc.

## CI test fixes (73878311)

### R14-1 — P3: cliprovider/provider_security_test.go утечка log.Writer

**Файл:** `internal/agent/cliprovider/provider_security_test.go:23-24`

```go
slog.SetDefault(slog.New(handler))
t.Cleanup(func() { slog.SetDefault(prev) })
```

Отсутствует capture/restore `log.Writer()` и `log.Flags()`. Это тот же
паттерн, который `cec10b5d` исправил в 8 других тестовых файлах после
live incident с ~64 GB memory blowup. В `cliprovider` он был пропущен.

**Влияние:** bounded by test binary lifetime (cliprovider — отдельный
пакет, отдельный binary). Внутри `go test ./internal/agent/...` бинаря
этот тест может оставить `log.Writer()` указывающим на мёртвый
`bytes.Buffer`, и последующие тесты в том же binary будут писать в
неработающий sink. Не растем безгранично (buffer умер вместе с тестом),
но слепляем stderr для остатка binary.

**Рекомендация:** добавить `prevLogOut, prevLogFlags := log.Writer(), log.Flags()`
и restore в cleanup, точно как в других исправленных файлах.

### R14-2 — P2: r5_2_rebuild_folderscope_symlink_test.go sibling path не resolved

**Файл:** `internal/agent/r5_2_rebuild_folderscope_symlink_test.go`

**Проблема:** `sibling := filepath.Join(workDir, "open.txt")` — raw join,
без `filepath.EvalSymlinks`. Когда `workDir` сам sits under symlinked
path component (macOS `/var` → `/private/var`, Windows junctioned CI
workspace), raw и resolved формы diverge, и `Check(sibling, ...)` не
матчит с уже-resolved grant'ом.

**Исправление:** `filepath.EvalSymlinks(sibling)` перед `Check`, точно
как `resolvedItem` уже делал двумя строками выше. Правильно, минимально,
отвечает точному контракту `FolderScope.Check` (требует already-resolved
path).

Failed on GitHub Actions `windows-latest` и `macos-latest` — теперь
зелёный.

### LibraryVirtualRoot re-export pattern

```
sdk/library_mode.go:    var LibraryVirtualRoot = tools.LibraryVirtualRoot
internal/agent/tools/fs_library_virtual_root.go: var LibraryVirtualRoot = libraryVirtualRootForOS()
```

Два определения одного константа. `sdk.LibraryVirtualRoot` re-export'ит
`tools.LibraryVirtualRoot`. Риск расхождений: минимален (один файл,
одна функция `libraryVirtualRootForOS`), но architectural smell —
два символа с одним именем в разных пакетах.

Today: безопасно. `tools.LibraryVirtualRoot` — canonical источник,
`sdk.LibraryVirtualRoot` — просто re-export. Если кто-то изменит
`sdk.LibraryVirtualRoot` напрямую (не через tools), компилятор не
предупредит о расхождении.

**Рекомендация:** либо сделать `sdk.LibraryVirtualRoot` явным re-export
через `= tools.LibraryVirtualRoot` (сейчас уже так), либо добавить
компиляционный assert в `sdk` package:
```go
var _ = func() {
    if LibraryVirtualRoot != tools.LibraryVirtualRoot {
        panic("LibraryVirtualRoot mismatch")
    }
}()
```
Но это избыточно при текущем коде — `var X = Y` гарантирует identity,
не копию.
