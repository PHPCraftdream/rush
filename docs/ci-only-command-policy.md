# CI-only command policy

`RUSH_DENY_EXEC` enables the process-wide command policy. Set it to `ci-only` to enable all built-in rules, or use a comma-separated selection: `go`, `linters`, `js`, `node`, `test-runners`, `python`, and `cargo`. An unset or empty value disables this policy. The environment value is read once during package initialization and inherited by child processes in the usual way; changing it later does not update the running policy.

The process policy is read once at package initialization. In-process subagents share that immutable policy; they do not depend on child environment inheritance, and changing or unsetting the environment later does not disable it. External child processes follow their own environment and may unset the variable, so this remains accidental-prevention policy, not a sandbox. The guard checks shell commands and structured argv before execution, including supported launcher and utility wrappers. Arbitrary interpreters, scripts, copied binaries, and indirect process creation can evade command-name checks. Tests, builds, linters, and benchmarks must run in GitHub CI, not locally under agent execution.

Tool options are scanned before policy subcommands so known operands (for example, `npm --prefix . test`) do not hide a denied action. Unknown options trigger a conservative scan of remaining argv for denied words; this can produce false positives when an unknown option takes a value, such as `npm --new test install`. Known option operands are consumed before scanning subcommands: `npm --prefix test install` is allowed because `test` is the prefix operand and `install` is not a denied CI action. Node `--test`/`--test-*` flags and test-named script paths are denied; ordinary scripts remain allowed. Inline options `node -e`, `--eval`, `-p`, `--print`, `-pe`, `-ep` (including attached code/long `=CODE`) and Python `-c` (including attached code) share an option parser. The guard does not execute inline code; it inspects simple literal child-process commands and literal argv arrays only. For Python `-m`, only `pytest` and `unittest` are denied.

External shell wrappers (`sh`/`bash`/`zsh`/`dash -c`, PowerShell `-Command`, and `cmd /c` or `/k`) fail closed under an active policy when their payload has a dynamic command head, uses `eval`/`source`/`.`, contains a dynamic action or required scanner operand for an enabled denied tool family, cannot be parsed, or reaches an unsupported opaque wrapper/depth. Literal safe command heads with dynamic ordinary arguments remain allowed. Use a literal allowed command instead; literal payloads are still checked against enabled rules. Passing a script file (`bash script.sh`, `sh .githooks/check_file_size.sh`, or PowerShell `-File`) is allowed by this wrapper preflight. PowerShell detection is conservative, and `cmd` percent expansion is refused.

This remains accident prevention, not a sandbox. Tests/builds/linters/benchmarks run in GitHub CI only. Scripts, copied/renamed binaries, arbitrary interpreters, user aliases/functions, make/task runners, and IDE/tool-launched commands outside Rush can evade command-name inspection. Inline Python subprocess checks and Node child-process checks are intentionally limited to simple literal string commands and literal argv arrays; dynamic code, computed commands, and unsupported call shapes remain opaque to this extractor. The scoped review is complete after these repairs; it is not an exhaustive spelling or execution-surface search.
