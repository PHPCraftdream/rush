## Pending integration and evidence limits

- `TestClientRunWithCredentialsMissingRequestedRoleFailsBeforeEffects` adds the SDK tenant-slot acceptance requirement: a configured custom role absent from the tenant credential set must fail with no session and no operator or tenant provider request. The test source requires `sql.ErrNoRows` from `client.Session` and empty fake-provider request lists, but CI is UNEXECUTED; do not report these assertions as passing or as an observed failure. The former mechanism validated the generic credential set during setup, resolved/created the session in `ExecuteRun`, and only checked requested-role credential coverage in downstream credential resolution. That ordering could leave a session row for a missing exact tenant slot, violating the SDK no-session assertion. `internal/app/app_run_setup.go` now makes the narrow correction after generic credential validation and coordinator capability checking: selected custom contract coverage requires the exact `creds.Models` key unless `AllowConfiguredRoleFallback` is explicitly true, before model overrides, MCP wait, resource preparation, and session resolution. Downstream coverage remains defense-in-depth; model construction is not duplicated. The SDK test's no-session assertion catches guard regression; the app preparation test source covers missing/wrong-case/wrong-spelling slots, valid exact/fallback/built-in exceptions, and malformed generic-credential precedence. CI remains UNEXECUTED.
- `TestRunCustomRoleProviderDispatch` invokes top-level Cobra in-process against a local HTTP provider; it proves provider-facing request/root-contract behavior, not an external CLI child boundary. `TestRunCustomRoleCLIChildDispatch` now covers the separate top-level-Cobra-to-fake-CLI-child boundary, including stdin prompt, distinct PID, custom model/effort, native-tool-disabled/allowed-tool argv, invalid-role no-child/no-session, and active migrated-Ktav deletion readback. It uses a copied test executable and the real Claude stream parser, not a real vendor backend; argv coverage is the native-tools policy floor and does not execute an inner tool or prove child-provider resume after process restart. This source is CI-only and unexecuted locally.
- The SDK facade, in-process top-level Cobra provider dispatch, top-level Cobra external fake CLI child dispatch, App-owned scheduler refresh, and independent test-helper process-lifetime sources listed above are present but CI-only and unexecuted locally. Evidence is limited to local fake-provider assertions rather than vendor behavior; fake CLI child/argv rather than real vendor behavior, inner tool execution, or process-restart provider resume; same-session prompt equality rather than evidence of stronger/new prompt generation; and native durable dispatch rather than full child-provider resume/network.
- The SDK fixture isolates both global data/config dirs and enables provider-cache-only mode; it retains SDK `options.data_directory` and nests `disable_default_providers` under `options`. The scheduler fixture likewise isolates both global dirs/cache-only, nests `disable_default_providers` under `options`, and asserts `ConfigDiskSyncRunning()` before relying on refresh. The process-lifetime fixture also uses nested `options.disable_default_providers`.
- The task74 acceptance tests cover installed-tool filtering and actual control-wrapper dispatch, including individual current-cap denial cases and multi-group inherited intersection. They do not prove every tool integration beyond the tested wrappers. `TestRoleToolGuardEnforcesCapturedAndCurrentCeilings` separately covers captured/current guard behavior.
- Task75 named tests assert refusal at resolver/delegation/batch-admission boundaries before their respective effects. They do not replace endpoint-specific evidence; the API `/tasks` no-side-effect assertions are in `TestAPITaskInvalidRolesRefuseBeforeCreatingSessions`.
- The API `/tasks` tests do not imply an end-to-end API `/tasks` assertion for SDK, CLI, or external-provider dispatch. The successful custom task uses a local fake provider and checks the exact outgoing model request separately from its response.
- No test or local CI execution is claimed. `FullCI42917788663` was independently API-verified by the main agent, but does not establish that the newly added/modified sources listed here ran or passed. Their execution status remains CI-UNEXECUTED.
