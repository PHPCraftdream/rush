## Decisions

- Reviewer-pass gate: `role==smart && reviewer configured` — НЕ требует, чтобы worker тоже был сконфигурирован (это отдельная, независимая ось). Причина: копирует уже устоявшийся паттерн `shouldBypassSubAgentBan` (role+config-presence, без флага), не усложняет комбинаторику.
- Reviewer-турн получает полный toolset (как обычный `--role reviewer`), а не урезанный — ModelRole=reviewer не триггерит orchestrator-strip (та логика завязана именно на ModelRole=smart+worker).
- `runStart`/`tokensBefore`/`costBefore` не сбрасываются между primary- и review-фазой — итоговый usage/cost/duration в envelope покрывает весь инвок целиком, не только reviewer-ход.
- Сетевой пакет (`internal/nettransport`) спроектирован полностью независимым от `internal/agent` — только `config.NetworkConfig` как общий тип; wiring — отдельная задача (Task B), что и подтвердилось полезным (пришлось нанять точный API уже ПОСЛЕ того, как Task A реально приземлился, а не гадать заранее).
- Для DNS-сервер+прокси комбинации — сделан bespoke DNS-over-TCP клиент (RFC 1035 §4.2.2 framing вручную), а не попытка форсировать `net.Resolver`'s внутреннюю framing-логику через подмену Dial — сознательный выбор, задокументирован в спеке и коде.
- Оба диффа (reviewer-pass, network Task A) сначала мержились в main как незакоммиченные изменения (default per CLAUDE.md "никогда не коммить без явной просьбы"); коммит/пуш выполнялся только по прямому запросу пользователя каждый раз отдельно — не переносил разрешение с одной пачки работ на другую.
