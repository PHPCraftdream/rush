## Session summary

Three strands: finishing the previous round's review follow-ups, splitting
every oversized file in the repository, and then a set of product decisions
the operator answered directly.

**The split was the bulk.** 30 files were over 1000 lines; 9 remain and 5 of
those cannot be split (three markdown files, a lockfile, a generated sqlc
file). Every Go split was pure movement verified by four measurements rather
than by reading the diff: the multiset of lines loses nothing, every top-level
declaration is byte-identical, every doc comment is still attached to its own
declaration, and for tests the `go test -list` inventory is unchanged. That
last check exists because a split that silently drops a test still compiles and
still passes.

**The checks earned their keep twice.** `config/load.go` arrived with four
stray blank lines, three of them between a doc comment and its function — in Go
that severs the comment from the declaration while gofmt, the compiler and the
tests all stay green. Only the doc-attachment check caught it. Separately,
seven agents were killed mid-run by the harness; four had finished, and their
diffs were accepted only after passing the same checks independently.

**`agent_turn.go` refused to split, and that was the right answer.** It is four
declarations, one of which (`runTurn`) is ~1577 lines. An analysis against five
safety criteria concluded against decomposition: 577 of those lines are
comments documenting fixed failure modes, ~570 of ~950 code lines are one
`agent.Stream` literal with a shared mutable capture web, and the code itself
records that a previous extraction (#243) caused a regression (#252). One safe
seam was extracted (`normalizeTurnError`); the rest was left with the reasoning
committed.

**#525 turned out to be a real bug, not a flake.** The symptom was a session
left "Untitled Session" with `context canceled` for both title models, about
1 full-package run in 27. The cause: `runTurn` calls `cancel()` explicitly
before returning, and the title context is derived from the turn's context, so
any title that had not finished was cancelled and only then waited for. It
looked like a flake because the existing test's mock answers instantly and
usually won the race. A new test delays the title 300ms and fails every time
without the fix.

**The background-job cap was NOT raised, and that is a measured reversal.** The
operator asked for 10x. At 500, internal/shell went from 5s to 149s and three
tests failed including timing-sensitive ones in another package; at 200 it was
one clean run and two failures. The jobs a higher cap admits are real processes
competing for the machine. Shipped instead: `CRUSH_MAX_BACKGROUND_JOBS` so the
operator can raise it deliberately, a warning at 80%, and a per-manager cap so
tests stop filling real queues.

**A live delegation smoke test confirmed the worker path works** — two `agent`
calls, the worker model (glm-4.7) executing 10 of 16 messages at 1/12 the cost
of the orchestrator — and incidentally exposed two sub-agent defects that are
noted below and unfiled.
