## Ключевые технические детали фазы 4 (для продолжения без контекста)

**Хранилище и законы:**
- **Одна правда.** Строка `async_jobs` — единственный источник состояния задачи. `Transition` — SQL CAS по `(owner, tool_call_id, claim_id)`. Поля outbox: `delivery` (none/pending/done/void), `wake`, `reacted`, `reacted_failed`, `wake_attempts`, `announced`, `notice_message_id`, `announce_message_id`. Таблица `session_notices` хранит уведомления без задачи (bg-shell, wake_failed и т.п.).
- **Живость хоста** определяется только замком ОС на файле хоста: `ProbeHost` (эксклюзивная проба), `ProbeHostShared` (читательская). «Неизвестно» считается «жив». Часов нет.
  - Восстановление (`RecoverDeadHost`) решает по разделяемой пробе. Эксклюзивный замок берётся только на удаление файла, записи привязаны к claim (R3A-3, R4A-1).
  - Сирот-файлы чистит `purgeOrphanHostLockFiles`.
- **Долговечный маркер драйвера** `session_drivers(session_id→host_id, pid)`: `rush run` владеет сессией между ходами без замка сессии. `ClaimSessionDriver`: CAS, мёртвый хост отбирается. Читатели: `ForeignLiveDriver`, `App.LiveSessionDrivers` (сырой SELECT на пуле чтения `App.readDB`).
- **Replay tool_call_id:** старая строка архивируется как `call_0#reused#uuid`. `job_kill` пишет id сообщения по claim (R3A-2), неименованную done-строку `job_kill` ретеншн не удаляет (R5A-1).

**Drain и реакция:**
- **Учёт.** Каждый Drain-проход учитывается ровно один раз в `accountDrainAttempt` по вердикту БД. Запуск разрешает единый предикат `drainPermitted` = политика + гейт сессии (пауза 60 с, `freeStreak`/`paidStreak`, спящий режим после 3). K=3 — закрытие по-строчно через `wake_attempts` и маркер `wake_failed`.
- **Что не считается попыткой.** Отказ до провайдера. Отмена оператором определяется по контексту хода (`operatorStop`). `ErrRunDefaultCap` оборачивает `DeadlineExceeded` (R8B-1).
- **Предел авто-ходов bg-shell в web.** 5 слотов на человеческое сообщение, слот тратится при допуске. Завершения «сверх предела» хранятся как множество id строк уведомлений (R5B-2). Повторная проверка откладывает запуск, только если весь долг — эти id. Проверка на старте хода (`decideDrainTurn`) идёт со `spent=false` под гейтом `bgArrival` (ctxMutex).
- **Ребёнок делегации.** Завершение bg-shell будит ребёнка, чья строка делегации `running` (`delegatedChildDriven`, R6B-1). Удержание завершения в менеджере оболочек (`PendingCompletionsOwned`): держит область ребёнка открытой, пока уведомление не зафиксировано. Истекает через 10 мин после выхода процесса или отсоединения (R7B-1, R8B-2). Stop перепроверяет каждого ребёнка дерева (R7B-2), устаревший исполнитель тоже (R8B-4).
- **Стоимость.** Расход ребёнка переносится родителю дельтой по `parent_cost_accounted`: в конце `runSubAgent`, при освобождении делегации (R6C-3), при выходе run'а ребёнка, в `chargeRunningChildren` на выходе CLI. Отрицательный `IncrementCost` (сброс) сначала доначисляет родителю (`decrementCost`); одна формула `owedChildCost` (R7A-1, R8A-4).

**CLI-цикл `rush run` (`internal/app/app_run_async.go` и соседние файлы):**
- **Порядок.** Claim драйвера → первый ход → `nextStep`: `CLIScope` = Owed/Paced/Deferred/Stuck/WorkOpen; ожидание `WaitForHint`, не реже раза в 5 с.
- **Проверки в ожидании.** Отмена (`stopError`: сначала кап, потом отмена) идёт через `exitPrecheck`. Лимиты `--max-cost`/`--max-tokens` проверяются на каждом пробуждении (R8B-3).
- **Ревьюер.** Запускается один раз при первом закрытии области (`scopeClosed`, `reviewerDone`). После чистого хода ревьюера цикл снова идёт через `nextStep`; Drain после ревьюера работают на его модели (`reviewerConfig`). Отказ ревьюера по замку пропускается с сохранением ответа (R6C-4).
- **Стоимость запуска.** Окно `startMark` (момент claim) … выход, плюс начисление бегущих детей.
- **Контракт `ended_reason`.** Пусто, пока запуск идёт. Единственный писатель — выход цикла (`persistEndedReason`); ходы цикла помечены `RunRequest.loopTurn` (R8A-1).
- **`cancel_requested`** — одноразовый флаг. Снимается при исполнении (выход цикла, прерывание внутри хода, но не у сессии, которую ведёт этот цикл) и при старте человеческого хода или возобновлении ребёнка. Drain его не снимает (R8A-2).
- **Потолок 6 ч по умолчанию.** Мягкий дедлайн (`installRunDeadline`), жёсткий `exit(124)` только через 60 с после дедлайна (R6C-5). Unix: SIGPIPE не убивает выход (`run_sigpipe_unix.go`, R8C-7).

**Поверхности `sessions`:**
- `why`, `list`, `watch`, `tail`, `locks`, `inject` видят живую работу (`inspectSessionLiveWork`: маркер драйвера, свои задачи, делегации).
- `locks` ищет маркеры по санитизированному имени файла (R7C-2), фильтрует по id (R8C-8).
- `reap` не трогает освобождённые (без PID) замки.
- `cancel --all` метит только сессии с живой работой.
- `reset` аннулирует async-долг сессии и отказывает при живой работе, даже с `--force` (R8A-3).
- `sessions show` и `list --json` показывают `ended_reason` и бюджет.
