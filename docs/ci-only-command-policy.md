# CI-only command policy

`RUSH_DENY_EXEC` enables the process-wide command policy. Set it to `ci-only` to enable all built-in rules, or use a comma-separated selection: `go`, `linters`, `js`, `node`, `test-runners`, `python`, and `cargo`. An unset or empty value disables this policy. The environment value is read once during package initialization and inherited by child processes in the usual way; changing it later does not update the running policy.

The process policy is read once at package initialization. In-process subagents share that immutable policy; they do not depend on child environment inheritance, and changing or unsetting the environment later does not disable it. External child processes follow their own environment and may unset the variable, so this remains accidental-prevention policy, not a sandbox. The guard checks shell commands and structured argv before execution, including supported launcher and utility wrappers. Arbitrary interpreters, scripts, copied binaries, and indirect process creation can evade command-name checks. Tests, builds, linters, and benchmarks must run in GitHub CI, not locally under agent execution.

Tool options are scanned before policy subcommands so known operands (for example, `npm --prefix . test`) do not hide a denied action. Unknown options trigger a conservative scan of the remaining argv for denied words; this can produce false positives when an unknown option takes a value, such as `npm --new test install`. Known option operands are consumed before scanning subcommands: `npm --prefix test install` is allowed, since `test` is the prefix operand and `install` is not a denied CI action. The `npm --new test install` example is the distinct unknown-option false positive. Ordinary Node scripts such as `node build.js` remain allowed; Node's `--test` and `--test-*` runner flags are denied. Python `-c` code and modules other than `pytest`/`unittest` are not analyzed.

External shell wrappers (`sh`/`bash`/`zsh`/`dash -c`, PowerShell `-Command`, and `cmd /c` or `/k`) fail closed under an active policy when their payload has a dynamic command head, uses `eval`/`source`/`.`, contains an opaque shell expansion, cannot be parsed, or reaches an unsupported opaque wrapper/depth. Use a literal allowed command instead; literal payloads are still checked against enabled rules. Passing a script file (`bash script.sh`, `sh .githooks/check_file_size.sh`, or PowerShell `-File`) is allowed by this wrapper preflight. PowerShell detection is conservative, and `cmd` percent expansion is refused.

This remains accidental-prevention policy, not a sandbox: copied binaries and interpreters can launch subprocesses indirectly. Python `-c` code is not analyzed for subprocess creation. Node `-e`/`-p` code is checked only for simple literal `exec`/`execSync` command strings; arbitrary JavaScript and unsupported `spawn` argv forms can evade command-name matching. Ordinary Node scripts such as `node build.js` remain allowed, while `--test`/`--test-*` runner flags and test-named script paths are denied.
