# Sprint 0 agent DM0b — the coord/agentrun SCC cut

**Status: analysis and plan only; no Go code, test or mapping file was changed by this pass.** Two artifacts accompany this document: the declaration ledger `docs/plans/2026-11-22-dm0b-ledger.tsv` (checked in, 494 lines, sha256 `10e1782306c0b036650fd35501b86deaf59eb0247610ca95fa318783a32177f0`) and a strict oracle tool under `.rush/tmp/sprint0/dm0b/oracle/` (not checked in).

The lane DM7 could not proceed as a plain move. This pass re-measured its premise on the live tree with an independent `go/types` graph, and the premise is wrong in its headline number: the strongly connected component that holds `coordinator` and `sessionAgent` has **57 atoms (23 types, 32 funcs, 2 vars) across 111 files**, not 195 types. DM7's 195 is reproducible from DM7's own graph and is an artifact of one shared blank-identifier node; deleting that node from DM7's graph yields exactly the 57 atoms measured here, with an identical member list.

What DM7 called "one blocked SCC" is therefore **two separable cores held together by one concrete field, one concrete type assertion, and four declarations filed under the wrong owner**. The plan is: four re-homings with no interface cost, one port of 14 names declared in `runtime/contract/agentcall`, one interface method, and a lane order that keeps every intermediate tree compiling.

Two limits are stated up front because they decide the lane, not the code:

- **`runtime/coord` cannot reach 7 files at 900 lines.** It carries 12,122 production lines; 7 files × 900 = 6,300. See §7 question Q1.
- **62 of the 536 root test files name both cores** and cannot stay white-box in either package. See §7 question Q3.

## 1. Method, inputs, reproducibility

### 1.1 The atom graph

The graph is built from the live package with `go/types`, not from text. Tool: `.rush/tmp/sprint0/dm0b/scccut/` (Go, module `scccut`, `go 1.27.2` — the repo's own toolchain, required because the tool's `go list -export` child emits export data the local `go1.26.0` importer cannot decode).

```
cd <worktree>
bash .rush/tmp/golock.sh ./.rush/tmp/sprint0/dm0b/scccut/scccut.exe \
  -repo <worktree> -pkg ./internal/agent -out ./.rush/tmp/sprint0/dm0b/graph
```

Outputs: `decls.tsv` (3,406 declarations with file, kind, name, receiver, exportedness, line span, atom), `refs.tsv` (14,231 distinct reference sites, each with the enclosing declaration, the referenced object, and a file:line), `atoms.tsv`, `files.tsv`, `meta.json`.

### 1.2 What an atom is

An **atom** is the unit that must move as a whole: a package-level `type` together with every method and struct/interface field declared on it; or a package-level `func`; or a `var`/`const` name. Methods and fields collapse onto their receiver type because a method cannot exist without its type — the plan's rule "methods must live in the package of their receiver" is exactly this collapse.

An **edge** A → B exists when a declaration inside atom A names a package-level object of B, **or** selects a field or method of a type B declared in this package. Both kinds matter: `type:sessionAgent → type:coordinator` is one field type plus 22 member selections.

### 1.3 Scope and limits

- The graph covers the **203 production files** of the `internal/agent` root package. `_test.go` files (536 of them) are excluded from the graph; §6.3 counts them separately by identifier footprint.
- Importers outside `internal/agent` (`internal/app`, `internal/serve`, `sdk`) are out of scope; the plan's lane DM8 owns them.
- Owner attribution comes from the two checked-in mapping artifacts, in this order of preference: exact `(source_file, symbol, kind)` row in `2026-11-16-sprint0-agent-execution.tsv`; then `(file, bare name, kind)`; then `(file, kind, bare name)`; then the file-level owner from `2026-11-16-sprint0-agent-layout.tsv`; then unowned. 975 atoms resolve exactly, 145 by file, 170 from the layout. Every owner claim below names the artifact it came from.
- SCC computation: Tarjan, run twice (iterative and recursive) on both this graph and DM7's, which all agreed on their own inputs (§2.3).

## 3. The cuts

The goal is directional, not symmetric: `coord` must end up importing `agentrun` and `agentcall`, and `agentrun` must import neither `coord` nor anything above it. Everything below is judged only by whether it achieves that.

### 3.1 C1 — the coordinator port (14 names)

`sessionAgent.coord *coordinator` (`agent.go:232`) and `SessionAgentOptions.Coord *coordinator` (`agent_options.go:32`) become a narrow port interface.

**Where the port lives:** `internal/agent/runtime/contract/agentcall`, new file `agentcall/agent_coord_port.go`. Not in `exec/agentrun`: `agentrun` implements nothing here, the coordinator does, so a port declared inside `agentrun` would force `coord → agentrun` *and* `agentrun → coord`. `agentcall` is below both.

**The import direction it creates:** `exec/agentrun → contract/agentcall` (already true of every root file that imports `agentcall`) and `runtime/coord → contract/agentcall`. `agentcall` imports only leaves — `internal/config`, `internal/session`, `internal/session/service`, `internal/session/state/sessionnotice`, `internal/store/message`, `internal/agent/prompt`, `internal/agent/safety/permission`, `internal/agent/tools` — and none of those imports any `internal/agent/runtime` package, so the new edge cannot close a cycle.

### 3.4 Why the result is acyclic — a simulation, not an assertion

Take only atoms owned by `coord` or `agentrun`, apply R1–R5, drop every other owner's atoms (as if lanes L1–L5 had landed), then delete every `agentrun → coord` edge (what C1 + C3 do):

| state | multi-node components | cross-owner edges |
|---|---|---|
| before the cut | **1 component of 31 atoms** spanning both owners | 18 agentrun→coord, 28 coord→agentrun |
| after the cut | **2 components, both intra-owner** (8 agentrun atoms; 16 coord atoms) | **0 agentrun→coord**, 28 coord→agentrun |

The two survivors are ordinary cycles *inside one package* — `sessionAgent`/`turnStream`/the two `newTurn…` factories in `agentrun`, and `coordinator`/`finalizationWiring`/the batch glue in `coord`. Intra-package cycles are not import cycles. The cross-owner graph is a single direction: `coord → agentrun`. So `coord` may import `agentrun` and `agentrun` may not import `coord`, which is exactly what the plan needs, and nothing in the cut creates a new edge — C1 and C3 delete edges, R1–R5 move declarations, and the only new import (`agentrun → agentcall`) lands on a package with no path back up.

## 4. Clusters that can leave the root now

The test for a **plain move** is one rule, applied in both directions:

> A set S of declarations can move to package P, while the root imports P, only if no declaration in S names an unexported name declared outside S, and no declaration outside S names an unexported name declared in S. If S also has no *outbound* edge to a declaration that stays behind, the move costs nothing but the file move.

The first half is what actually bites: a reference from S to a root declaration forces `S → root`, and since the root imports `S`, that is a cycle. Outbound edges are therefore the hard blocker; inbound edges are the export cost.

### 6.2 Behaviour risk, ranked

1. **C1's field accessors (§3.1).** `a.coord.arb` becomes `a.coord.Arb()` or a port method that returns the arbiter. The call shape changes; the state does not. Risk is a wrong receiver or a nil-guard lost in translation (`agent_turn_step.go:464` guards `ts.a.coord != nil` before the call — the port must keep that guard).
2. **C1's component fields.** Six of the seven fields (`arb`, `finalization`, `subAgentDrivers`, `background`, `driverHints`, `cfg`) are components that L5 moves elsewhere. Doing C1 before L5 fixes an interface around fields that are about to disappear; doing it after L5 leaves fewer names. The lane order above puts L5 first for this reason.
3. **C3's new interface method.** Every `SessionAgent` fake grows a method. If one is missed, the failure is a compile error in a test file, which is the cheap direction.
4. **R1–R5's re-homing.** A declaration that changes package also changes its `init()` order relative to its neighbours inside the old package. Only two `init()` exist in the whole package (`coordinator_recheck.go:27`, `drain_attempt.go:57`), both atomic stores, and neither is in this list.

## 7. Operator questions

**Q1 — `runtime/coord` and `exec/agentrun` cannot both be 7 files and 900 lines.**
`coord` is 63 files / 12,122 production lines; `agentrun` is 30 files / 9,948. Seven files at 900 lines is a 6,300-line budget. Coord is 5,822 lines over; agentrun is 3,648 over. Even after L5 removes the component bodies (17 files, 5,581 lines, most of them coordinator-side methods), `coord` remains near 8,000 lines — nine or ten files, not seven. Options: (a) relax the 7-element limit for these two directories only, as a ratcheted allowlist entry that only shrinks; (b) keep 7 elements and relax the 900-line limit to ~1,750 for these two; (c) push more declarations out of `coord` into `batchinst`/`finalize`/`modelkit` by declaration-level reassignment (the manifest vs layout disagreement in §9 shows ~1,700 lines of candidates), which is real work and changes other lanes. **Recommendation: (c) first, then (a) as a ratchet if (c) falls short** — (c) is the only option that does not bend a rule the rest of the sprint is held to, and the disagreement list already names the files.

**Q2 — does `agentcall.SessionAgent` grow a `ShuttingDown()` method?**
Today `finalization_queue_reservation.go:82,103` reads an unexported `atomic.Bool` through a concrete assertion (C3). The alternative is one more method on the 25-method contract interface that every fake in the repo implements. Options: (a) add `ShuttingDown() bool` to the interface; (b) move the two admission checks into the agent (the queue asks the driver instead of type-asserting it); (c) leave the finalization queue component in the root until a later pass. **Recommendation: (a).** It is one method whose implementation is a single atomic load, it is the only option that keeps the check where it is, and (b) changes which goroutine observes the flag — a real behaviour change for a shutdown race.

**Q3 — where do the 62 two-core test files go?**
Each names both a coordinator and a sessionAgent identifier, so it cannot compile inside either package once they are separate; the identifiers are unexported, so it cannot become a black-box test either unless the identifiers it uses are exported or the test is rewritten against the public surface. Options: (a) split each file by footprint where it splits cleanly; (b) move the remainder to `internal/app/itest` and rewrite them against exported entry points; (c) leave a deliberate root test package that imports both (`package agent_test`), accepting that the root keeps a test-only element. **Recommendation: (a) for the ones that split, (b) for the rest**, with (c) rejected because it keeps the root directory alive as a code directory and re-opens the element count.

**Q4 — R1–R5 are manifest corrections. Who owns the mapping artifacts?**
Five declarations filed under `agentrun` take `*coordinator` and cannot move there; for two of them the layout TSV already says `coord`. Fixing the manifest is not a code change but it changes what every later lane replays. **Recommendation:** treat `2026-11-16-sprint0-agent-execution.tsv` as superseded for these five rows and record the correction in the lane's ledger rows rather than editing the 4,291-row TSV in place.

**Q5 — may the ledger's scope grow?**

Extending it to all 203 root files would make it a 10,227-row file. **Recommendation:** keep the 12-file scope for this lane and add one file's worth of rows per lane as that lane starts, so the ledger stays reviewable and the oracle stays strict about what it does cover.

## 8. The strict oracle

### 8.1 Contract

`.rush/tmp/sprint0/dm0b/oracle/` (Go, module `oracle`, `go 1.27.2`). Two commands.

```
oracle census -dir <pkgdir> -out <census.tsv>
oracle verify -dir <pkgdir> -census <baseline.tsv> -ledger <ledger.tsv>
```

`verify` exits 0 only on a clean pass, 1 on any failure, 2 on usage error, and it *panics* — deliberately, non-zero — if the baseline census itself contains a duplicate key.

Strictness, as required of a follow-up lane oracle:

- **Rows are keyed by file, kind, symbol, source line and end line.** A declaration's identity is `file|kind|symbol|line|end`, so two declarations with the same name are distinct when they are on distinct lines. The three blank-identifier compile-time assertions in `coordinator_iface_assert.go` — `var _ ReactionDebtSource = (*coordinator)(nil)` at lines 11, 12 and 13 — are therefore three rows with three different hashes, and the census asserts that there are exactly three.
- **Bodies are hashed as normalized token streams**, not bytes: explicit and implicit statement separators are made to agree, and a trailing separator before `}`/`)`/`]` is dropped, so gofmt-only rewrites do not move a hash.
- **Thin wrappers are validated by shape, not by name.** A `wrapper` row passes only if the live declaration's form is `thin_delegate` — one statement, a `return`/call of a package-qualified or package-local function whose every argument is a parameter or receiver name — and its token count is ≤40.
- **Embedded fields and methods are inventoried by receiver.** Every method appears as kind `method` with symbol `Recv.Name`; every struct field and interface method appears as kind `field`/`interface_method` with symbol `Recv.Name`; an anonymous (embedded) field carries `embedded=true` and its symbol is the embedded type's name. In the root package the baseline census holds 10 embedded fields and 219 `thin_delegate` declarations; across the whole `internal/agent` subtree it holds 39 and 300.
- **Failure modes**: `mismatch` (a declaration moved without a row, changed body, or a `wrapper` that does not forward), `ambiguous` (more than one candidate at a destination), `missing_row` (a ledger row whose declaration is not in the baseline — i.e. manifest drift), `unexpected_duplicate` (two live declarations with the same key), `claimed_twice`, `unclaimed_declaration` (a declaration in a scoped file that no row covers), `blank_identity`, `baseline_mismatch`, `duplicate_row_id`, `out_of_scope`.
- **Known gap, left open on purpose**: the `absent` disposition verifies that a declaration is gone and that no declaration with its recorded body hash survives, but it does not scan the tree for remaining *references* to the retired name — the tool's reference walk returns nothing. A lane that retires a declaration must therefore also show, by its own grep, that no live production file still names it. Every other disposition is fully checked.

```

exit=0
```

### 8.3 It fails when it should

Three mutations, all in scratch copies; the tree was never modified.

| mutation | result |
|---|---|
| one hex character flipped in the `hit` of `agent.go / sessionAgent.coord` in a copy of the baseline census | `FAIL baseline_mismatch DM0B-125 …` / `failures=1 pass=false` / exit 1 |
| two blank assertions on one physical line in a scratch copy of the 12 files | `FAIL unexpected_duplicate live tree declares _ twice at coordinator_iface_assert.go:12` + `FAIL blank_identity DM0B-204 … found 2` / exit 1 |
| `finalizationQueueComponentHostAdapter.readyWait` deleted from a scratch copy | `FAIL missing_row DM0B-298 ledger row DM0B-298 has no baseline declaration …` / exit 1 |

A fourth observation is worth recording: pointing `-census` at a *duplicated* census makes the tool panic on the duplicate census key before it can report anything else. That is the intended fail-closed direction — an ambiguous baseline is refused, not resolved.

### 8.4 Using it for a lane

1. `oracle census -dir ./internal/agent -out <lane>/before.tsv` before touching anything.
2. Give every declaration of every file the lane touches a row: `present` if it stays, `moved`/`wrapper`/`exported`/`absent` if it goes, `noop` for blank identifiers. Add one `scope` row per touched file.
3. `oracle verify -dir ./internal/agent -census <lane>/before.tsv -ledger <lane>.tsv` must print `pass=true`.
