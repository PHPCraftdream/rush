## Work in flight (UNCOMMITTED)

Two files changed for #551, both building and vetting clean:

- `internal/session/run_queue_entry_exec.go` — `execCtx` now derives from the
  caller's `ctx` instead of `context.Background()`. That parameter was
  previously unused entirely, which is what made `--timeout` unable to stop a
  started continuation and let a drain outlive shutdown.
- `internal/session/run_queue_entry_dispatch.go` — the background path now
  passes `p.ctx` rather than the tick's context. **This half is essential and
  nearly got missed**: the tick's context is a SCAN context with a 5-second
  deadline, so honouring the parameter without splitting the parents would have
  capped every durable turn at five seconds.

Not yet done for #551: `DrainSessionNow` still does not register in `workerWg`,
so `Stop()` does not wait for it, and it drives `inFlight`/`execSem` itself,
bypassing the admission gate. No tests written yet. Nothing committed.

## Decisions

- **The background-job default stays 50.** Raising it to 500 was measured to
  destabilise the suite (one package 5s -> 149s, timing-sensitive tests in
  another failing); 200 gave one clean run in three. The knob went to the
  operator as `CRUSH_MAX_BACKGROUND_JOBS` instead, plus a warning at 80%.
- **`runTurn` is not decomposed.** Verified all three supporting facts myself.
- **Provenance = the executing model**, applied to BOTH the message row and its
  usage record so the two cannot disagree.
- **The update check polls the fork, not upstream.** It 404s today because the
  fork publishes no releases, so no notice is sent — correct, and it starts
  working when a release is cut.
